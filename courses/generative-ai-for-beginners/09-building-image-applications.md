# 09 · 图像生成应用

> 原课程解读与中文重写；「工程补充」为额外实践。核对日期：2026-10-03。

## 图像生成应用的核心

文本生成图片，把自然语言约束变成视觉结果；图像编辑还需要原图、编辑范围和变化要求。原课在本次快照中使用 GPT Image 家族，而非只保留旧 DALL·E 例子。

模型家族、可用地域、参数与输出格式会变化。本章解释流程，不把快照中的“最新型号”或可用状态当作长期保证。

## 提示如何写得具体

| 维度 | 示例 |
| --- | --- |
| 主体 | 正在整理书籍的学生 |
| 场景 | 明亮的学校图书馆 |
| 构图 | 横版，主体靠右，左侧留标题空间 |
| 风格 | 清晰、柔和的教育插画 |
| 光照与色彩 | 日间自然光，暖色为主 |
| 约束 | 不出现真实校徽，不添加文字 |

与“帮我画一个好看的图”相比，这样更容易评价结果。对同一系列图像应复用主体描述、配色和参考图，但一致性仍需要人工或自动视觉验证。

## 原课的响应处理

快照中的生成示例读取 b64_json，解码为字节并保存 PNG。不能把所有图像接口都假设为返回可下载 URL，也不能对所有格式统一加 .png。服务给出的媒体类型、尺寸与错误响应都需要校验。

~~~python
import base64
from pathlib import Path

# item 是供应商成功响应中的一个图像条目。
image_bytes = base64.b64decode(item.b64_json, validate=True)
Path("output").mkdir(exist_ok=True)
Path("output/example.png").write_bytes(image_bytes)
~~~

这是输出处理片段，不是完整生成请求，也没有在线执行。

## 图像编辑与 Mask

编辑请求需要明确保留与改变内容。Mask 通常定义编辑区域，但透明度含义、尺寸要求及格式依服务而定。编辑前核对原图与 mask 的空间对齐，否则可能改错位置。

原图带透明背景时，应把透明度要求显式写入任务并验证 alpha 通道。不能只看缩略图背景像白色就判断透明度是否保留。

## 不要从例子推断未公开架构

扩散模型常通过逐步去噪生成图像，但不是所有图像模型都能用同一具体架构解释。原课中的架构概述适合理解一般机制，不能据此确认专有模型的所有内部实现。

## 生产流程〔工程补充〕

输入检查 → 生成任务 → 保存结果 → 尺寸及格式验证 → 内容与品牌检查 → 用户选择 → 正式发布。生成耗时较长时使用任务状态和结果 ID，避免网页刷新后重复生成并重复计费。

生成的图中文字可能错误；精确流程图、地图、数据图表应用可验证的绘图程序。把“当前表现不错”当成“像素和事实都精确”会造成后续风险。

## 成本与缓存

尺寸、质量、数量、编辑输入都会影响成本或延迟，具体以接口为准。缓存键应包含提示、参考图摘要、参数与版本，不能只用一句用户提示。缓存还需考虑访问权限与图像有效期。

## 练习

设计三种相同内容的教育插图：纯文本提示、加入构图限制、加入参考图。评估主题准确性、文字错误、风格一致性和留白是否满足排版。保存提示和参数，便于复现与调整。
