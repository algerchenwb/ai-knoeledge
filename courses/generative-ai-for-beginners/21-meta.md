# 21 · Meta Llama 模型案例

> 原课程解读与中文重写；「工程补充」为额外实践。核对日期：2026-10-03。

## 本课的定位

原课以 Llama 3.1 与 Llama 3.2 说明工具调用、多语言、视觉能力和小尺寸部署。它们是教学快照中的系列，不代表 Meta 当前全部产品，也不保证服务端点对所有版本开放。

## 模型名字应该怎么读

版本号表示系列演进，参数量反映规模，Instruct 表示做过指令适配，Vision 表示特定变体支持图像。不能看到 Llama 3.2 就断言它所有变体都接受图片；原课同时介绍了文本小模型与视觉变体。

模型最大上下文、服务输入限制和最大输出长度是不同概念。部署接口可能比模型标称窗口更小，必须分别核对。

## 原生工具调用不等于工具已接好

课程展示 Brave Search 与 Wolfram Alpha 风格的工具建议。模型生成特殊 token 或函数调用文本，不会自动获得搜索账号、网络权限或执行器。应用仍需实现工具、授权、参数验证与结果回传。

~~~text
模型：建议 brave_search.call(query="示例城市天气")
应用：识别并验证调用
工具：通过已授权客户端获取真实结果
应用：将结果回传模型
模型：根据真实结果回答
~~~

不要使用 eval 直接运行调用字符串。特定模型原生格式与服务提供的规范化 tools 响应也可能不同，要用明确适配器转换。

## 视觉理解怎么用〔工程补充〕

提供图片和明确问题，例如“提取表格列名，无法看清的单元格标为未知”。模型看到的图像尺寸和压缩影响细节。远程图片地址要控制来源，避免请求内部资源。

视觉模型能描述图像，不保证精确 OCR、计数、空间测量或诊断。表格可结合 OCR 与结构校验；地理或财务精确值要核对原始数据。

## 开放权重与许可证

Llama 的具体许可并不等同于普遍的 Apache 或 MIT。阅读对应版本条款和模型卡，确认部署与再分发条件。中文知识笔记不应把“开放权重”简化成“没有使用限制”。

## 合成数据

模型可生成训练样本草稿，但要去重、验证事实、检查许可证与隐私，再进行独立划分。生成模型和评测模型高度相似时，评分可能偏好熟悉表达。更大模型生成的每条样本也不自动正确。

## 迁移到自己服务

固定权重和 tokenizer 版本，使用正确 chat template，验证视觉预处理和工具输出格式。自托管仍需监控、资源预算、权限和漏洞修复。通过托管平台调用则要记录服务端实际部署版本。

## 练习

准备文字查询、图片表格、工具查询三类任务，记录哪些变体支持输入、哪些步骤需要外部工具。自查：模型答出当前天气是否证明它查询过？不证明，需要真实工具执行记录与来源。
