# 16 · 开放模型与 Hugging Face

> 原课程解读与中文重写；「工程补充」为额外实践。核对日期：2026-10-03。

## 为什么要理解开放模型

开放模型让团队可以下载、部署、量化和微调权重，获得更多控制。课程通过 Hugging Face、Llama、Mistral、Falcon 等案例介绍选择路径。这些具体型号属于课程历史案例，不是当前产品排行榜。

## 开放到什么程度

权重可下载、推理代码公开、训练代码公开、数据可获得，是不同层次。原课也提醒很多模型不能直接按传统软件的开源概念归类。使用前读取具体型号与版本的许可证，而不是凭模型家族名决定。

许可证可能影响商用、再分发、衍生模型与使用场景；模型仓库中的代码许可证不一定等于权重许可证。

## Hugging Face 仓库里看什么

| 资产 | 作用 | 检查重点 |
| --- | --- | --- |
| Model card | 说明用途、限制与训练评测 | 语言、任务、风险 |
| Config | 定义架构等配置 | 推理引擎兼容性 |
| Tokenizer | 文本编码与模板 | 与权重是否匹配 |
| Weights | 模型参数 | 版本、格式与体积 |
| Chat template | 对话与工具输入格式 | 角色和特殊 token |
| License | 使用条件 | 是否满足业务要求 |

基础模型适合继续训练等场景；指令调优模型通常更适合问答。但名字中的 Instruct 不是效果保证，仍需评测。

## 本地部署要做什么〔工程补充〕

固定仓库 revision；选择兼容引擎；下载所需文件；准备合适精度；应用正确模板；验证中文、长文本与工具格式；封装为受控 API；记录模型与运行时版本。

部分仓库要求运行自定义代码。开启 trust_remote_code 会执行仓库代码，应在明确审核和隔离后使用。模型文件同样属于供应链资产，要管理来源与变更。

## 不要混淆 Dense 与 MoE

Dense 模型通常在每次前向中使用主体网络；MoE 通过路由选择部分专家参与某些层的计算。不是所有 Mistral 型号都是 MoE，也不能仅凭家族品牌推断架构。MoE 的总参数量与激活参数量不同，但未激活专家仍可能需要存储或调度。

## 部署成本

权重大小只是下限。服务还需 KV cache、计算缓冲、运行时开销，并受上下文、并发与批处理影响。若 GPU 长期闲置，本地成本未必低于 API；如果请求量大且稳定，自托管可能更适合。结论要来自真实负载测量。

## 排查效果下降

同一权重在不同运行时效果不同，先核对 tokenizer、chat template、停止符、量化版本与上下文截断。工具调用失败也可能是模板或输出解析错，不一定是模型能力不足。

## 练习

选择一个具体开放模型，做一张部署档案：revision、许可证、精度、上下文、模板、运行时、硬件和评测结果。做到别人能依档案复现实验，而不是只写“使用某某模型”。
