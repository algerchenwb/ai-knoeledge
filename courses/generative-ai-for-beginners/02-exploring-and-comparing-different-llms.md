# 02 · 模型分类与选择

> 原课程解读与中文重写；标为「工程补充」的内容是额外实践，不是原仓库承诺。核对日期：2026-10-03。

## 选择模型是在选择任务能力

课程区分基础模型、语言模型、开放权重模型、专有模型，以及文本、向量和图像模型。业务先明确任务，再比较模型：生成、分类、检索编码、视觉理解和工具调用需要的能力不同。

## 重要分类

基础模型是可以适配多类任务的预训练模型；LLM 是其中处理语言的一类。Embedding 模型将内容变成向量，常用于检索，不负责生成最终答案。图像生成模型产出图像；视觉语言模型通常理解图像并输出文本，不能直接视作图像生成器。

Encoder 通常擅长形成输入表示，Decoder-only 常用于逐 token 生成，Encoder-Decoder 先编码输入再生成输出。它们是架构类别，不是业务质量排行。

## 开放权重、开源与托管服务

开放权重表示可以获取权重，不自动意味着训练数据公开、训练流程完全可复现或商用无限制。开源资格与具体许可证有关。闭源托管服务减少部署工作，但需要考虑数据处理、地域和供应商依赖。

服务名与模型名也不同：一个聊天产品可能在后台路由不同模型。比较时要记录实际模型版本、端点配置与参数，否则结果不可复现。

## 建立自己的选型表〔工程补充〕

| 维度 | 如何测 | 为什么重要 |
| --- | --- | --- |
| 中文业务理解 | 同一批真实问题盲评 | 英文基准不等于业务表现 |
| 参数提取 | 字段准确率、缺项识别率 | 决定接口调用能否成功 |
| 工具选择 | 正确工具与错误工具次数 | 避免调错 API |
| 检索回答 | 证据支持率、引用准确率 | 防止有引用仍答错 |
| 延迟 | 首次输出、整体 P50/P95 | 平均值掩盖长尾 |
| 成本 | 每个成功任务总成本 | 多次重试可能抵消便宜单价 |
| 稳定性 | 超时、限流、重复运行差异 | 决定上线体验 |

先构造一个可管理的小评测集，例如 50 个脱敏任务，这是起步规模，不是通用标准。包含正常问题、信息缺失、歧义、长上下文和恶意输入。用相同工具、资料与预算跑多个候选，记录每次结果，不只挑最好的一次。

## 提示词、RAG、微调怎么选

- 不理解输出规范：先改提示词并提供示例。
- 缺少公司文档或当前事实：优先检索或 API。
- 输出行为长期不稳定且已有高质量样本：再评估微调。
- 完全不同能力需求：更换适合任务的模型类别。

模型路由也可行：简单分类由低成本模型处理，复杂规划交给更强模型。但路由器会新增延迟和误判，必须与单模型基线比较。

## 常见误区

“大模型一定更好”“上下文越长越能找到答案”“开放权重一定更便宜”都没有普遍保证。本地部署费用还包括 GPU、闲置容量、监控和运维。长输入可能把关键资料淹没，评估应包含关键事实处于不同位置的样本。

## 练习

给三个候选模型同样的 20 条 API 参数提取任务，计算成功率和平均重试次数。选型结论应写成“在这个任务集与配置下更合适”，而不是宣布一个永久赢家。
