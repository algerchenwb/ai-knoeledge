# 第01课深化：从 token 到生成，以及为何需要验证

> 对应 [第01课概览](../01-introduction-to-genai.md)。固定上游快照 d8ec07e31c4b32bd283d565c1abd9b58bb5cf2e8；核对日期 2026-10-04。
> 本文聚焦自回归文本模型的入门机制，不将它推广成所有生成模型或所有多模态架构。

## 1. AI、机器学习、深度学习与生成式 AI

AI 是较广的研究与应用领域；机器学习从数据中学习规律；深度学习使用多层神经网络。现代生成式 AI 大量采用深度学习，但历史上也存在其他生成方法。LLM 聚焦语言相关建模，不能把所有图像、音频生成模型统称为 LLM。

分类器通常在既定标签中选择；生成模型构造内容。二者可以组合：模型先生成候选回答，确定性检查或分类器再判断是否可展示。

课程以虚构教育创业项目串联应用。目标不是“做一个能聊任何话题的系统”，而是把学习辅导、搜索、报告等需求逐步落实成可评估功能。

## 2. token 不是固定数量的字符

Tokenizer 把文字转换成 token ID。token 可能对应一个字、词片段、标点或其他片段；中文、英文、代码和数字的切分方式依 tokenizer 而异。

例如“北京今天天气怎么样”不能靠肉眼可靠判断有几个 token。同一句话在不同模型中可能有不同 token 数。空格、特殊 token、工具定义和对话角色模板也可能计入输入。

上下文预算包含的不只是用户问题：

```text
系统说明 + 工具定义 + 历史 + 检索证据 + 当前问题 + 输出预留
```

具体服务如何计算与限制输入、输出，应查看该模型的协议。不应把某个字符/token 比例当成所有中文请求的精确计费算法。

## 3. token ID、embedding 和向量搜索要区分

token ID 是离散编号，不具有“编号越近，语义越近”的保证。模型内部通常把 ID 转换成可学习的向量表示，并经过多层计算。

用于语义搜索的 embedding 则通常是对整段文本输出的向量表示。它和语言模型内部 token 表示有关联思想，但不是可任意互换的同一个接口。用不同 embedding 模型生成的向量，即使维度相同，也不应直接混在同一个检索空间中。

详见 [第08课](08-semantic-search-and-indexing.md)。

## 4. 自回归生成的直观过程

模型根据已有 token 计算下一个 token 的分布，选出一个 token，再继续计算。生成的早期错误会进入后续上下文，因此后面的文字可能围绕错误前提继续展开。

一个简化概率表示：

```text
P(完整输出 | 输入)
= P(y1 | 输入)
  × P(y2 | 输入, y1)
  × ...
  × P(yn | 输入, y1...y(n-1))
```

这是解释分解的数学表达，不代表模型执行数据库事实核验。模型能生成可信措辞，不表示每句话都经过独立证据检查。

Attention 让模型按上下文关系组合信息。位置编码等机制仍负责序列信息；不能把“可关注远处内容”解释成模型不需要顺序或永远能准确找到长文本中的证据。

## 5. 预训练、适配和推理

| 阶段 | 主要发生什么 | 是否更新权重 |
|---|---|---|
| 预训练 | 从大量数据学习语言及其他规律 | 是 |
| 监督微调等适配 | 学习任务或响应方式 | 通常是 |
| 普通推理 | 根据当前输入生成输出 | 通常否 |
| RAG | 把检索资料加入推理上下文 | 本身不要求 |
| few-shot 提示 | 在当前输入中提供示例 | 普通调用不要求 |

聊天记忆、应用保存的摘要和模型权重是不同层。对话中纠正了模型，不意味着服务已经永久训练了所有未来请求。具体平台的数据使用规则需要另外查看，不能由这个机制结论反推平台隐私政策。

## 6. temperature 为什么不等于事实开关

在常见采样实现中，temperature 调整输出分布的尖锐程度，top_p 限制候选概率质量范围；具体支持和交互依模型接口而异。

- 更保守的采样可能减少变化，但仍会稳定输出错误。
- 更随机的采样可能增加多样性，不保证更有创意或更正确。
- temperature=0 也不应被当作跨硬件、版本和服务实现的绝对逐字一致保证。
- 模型生成的“我有99%把握”通常不是经过校准的准确率。

应固定采样配置用于可比较实验，使用事实依据和验证提高可靠性。

## 7. 三种不同的错误

**输入不足**：问“这个区域客流怎样”，却未提供区域、月份、人群定义与数据。   
**证据处理错误**：资料存在，但模型遗漏条件、混淆分母或合并冲突来源。   
**生成错误**：在缺少证据时给出具体数值、虚构引用或不合法 JSON。

它们需要不同修复。第一类补充结构化上下文，第二类改善证据组织与评估，第三类加入拒答、验证与结果边界。只换模型或增加“认真回答”不能保证修复。

## 8. 将“区域洞察”拆成模型与程序职责

工程示例：用户要求解释某区域客流同比变化。

程序负责解析可信区域 ID、查询授权数据、确定月份与统计口径、计算同比、处理零分母并记录来源。模型负责把已验证数据整理成可读解释，并明确尚未有证据支持的原因。

如果只观察到客流下降，不能自动写成“因为新商场开业”。原因需要额外证据；相关性也不能直接写成因果关系。模型输出中的区域、月份、数值和引用应与可信结果逐项核对。

## 9. 生成内容的验收分层

| 层 | 问题 | 验证方式 |
|---|---|---|
| 语法 | 能否解析？ | JSON解析、类型检查 |
| 契约 | 字段与枚举正确？ | Schema、范围 |
| 事实 | 是否与证据一致？ | 原文、数值、引用核对 |
| 权限 | 是否允许读写？ | 服务端授权 |
| 体验 | 用户能理解并纠正？ | 可核查来源、恢复流程 |

通过上一层不意味着下一层通过。合法 JSON 可能含错误数字；真实数字也可能来自当前用户无权访问的数据。

## 10. 练习

设计“从邮件提取日期”的任务，覆盖明确日期、没有日期、多个冲突日期和恶意附加指令。规定缺失或冲突时如何返回，保存每条的预期结果。

自测答案方向：token 是模型特定切分单位；推理通常不更新权重；流畅性不提供事实保证；降低采样随机性不能消除事实错误。
