# 08 · 语义搜索深化：Embedding、切块、相似度、索引与评测

> 第08课深入解读，核对日期：2026-10-04。来源固定于提交 d8ec07e31c4b32bd283d565c1abd9b58bb5cf2e8。标为「工程补充」的内容为原创实践。

## 1. 搜索与生成回答是两种任务

搜索的交付是“相关材料在哪里”，生成回答的交付是“依据材料说明问题”。第08课主要实现前者：用户问一个问题，返回相关视频片段及跳转时间。这个搜索应用不必先调用聊天模型生成一段回答。

这一区分很重要。搜索找到错误片段，后续模型很难可靠地修正；搜索找到正确片段，模型也可能在解释时加入材料外内容。检索与生成应分别评测。

原课程的视频索引说明其素材截至2023年10月。即使程序今天能运行，也不意味着索引涵盖此后发布的视频。

## 2. Embedding 是什么

Embedding 模型把文本映射成一串数值，称为向量。它把文本的某些语义关系编码到向量空间中，使“意思相近但措辞不同”的内容有机会靠近。

例如“怎么生成查询语句”与“自然语言转 SQL”可能在语义上接近。具体相似程度取决于模型训练、领域、语言和文本长度，不能假定一定召回。

一个向量维度不是“年龄”，另一个不是“职业”。通常不能给每一维分配独立、稳定、人工可读的含义。向量也不是可以直接还原为原文的压缩文件；检索结果需要用 chunk_id 找回原文。

原课的1536维是特定示例模型的输出维度，不是 Embedding 的通用常数。不同模型和配置可能输出不同维度。

## 3. 关键词检索与向量检索怎么配合

| 场景 | 关键词检索的价值 | 向量检索的价值 |
| --- | --- | --- |
| 接口名称、错误码、表名 | 保留精确字面匹配 | 容易被相近语义干扰 |
| 用户换一种说法问问题 | 可能依赖词汇扩展 | 可召回语义相关内容 |
| 业务定义与否定条件 | 可定位明确术语 | 仍需检查逻辑含义 |
| 型号、版本号、ID | 适合精确过滤 | 相似不等于相同 |

原课程用较简单的例子比较两者。真实关键词系统也可以使用分词、词干、同义词等能力，并非只能逐字匹配。向量搜索也不是总能理解用户意图。

API Agent 文档检索尤其适合组合：用户说“查附近客流”，向量检索帮助找到相关功能；一旦解析出明确接口名、参数名或数据表，应保留精确匹配约束。

## 4. 原课程的索引流水线

课程介绍的准备过程：

1. 下载视频转录文本。
2. 尝试从开头3分钟提取讲者。
3. 按3分钟片段切分，并带约20词重叠。
4. 生成约60词摘要。
5. 对片段原文生成向量。
6. 保存片段、向量、摘要与视频定位信息。

两个容易混淆的点：

- 摘要和向量是不同资产，生成摘要不等于生成向量。
- 向量对应的是片段原文；摘要不应被误认为完整证据。

本章正文明确给出上述流程，脚本说明还引用了另一个数据准备仓库。若要重建索引，需要继续检查脚本和依赖，不能仅凭这一页推断索引可直接重建成功。

## 5. 切块为什么影响搜索

块太小，定义与例外可能分离；块太大，多种主题混在一个向量中，难以精确定位。

例子：一份指标文档先定义“近90天去重人数”，后面说明“排除零时长记录”。如果切块只保留第一句，模型可能检索到不完整口径。

重叠可以减少边界丢失，但会增加存储与候选重复。不能把前10个相似片段都来自同一段文档当成10份独立证据。

不同资料需要不同切块方式〔工程补充〕：

| 资料 | 优先考虑的结构 | 需要保留 |
| --- | --- | --- |
| 视频转录 | 时间片段与主题段落 | 视频ID、起止时间 |
| 接口文档 | 接口及参数表 | 方法、路径、字段、版本 |
| 指标说明 | 定义、公式、限制 | 业务口径和例外 |
| 代码 | 函数、类型与模块 | 文件路径、符号、提交 |
| 长文档 | 标题、段落、Token预算 | 标题层级、来源位置 |

固定3分钟是视频案例的选择，不是所有知识库的最佳切块方式。中文文档也不能简单把“20个英文词”换成20个汉字而假定效果相同。

## 6. 余弦相似度的公式与边界

```math
\operatorname{cos}(q,d)=\frac{q\cdot d}{\|q\|\|d\|}
```

它比较方向，取值理论上位于[-1,1]。如果两个向量已归一化为单位长度，点积就是余弦相似度。

例子：q=(1,0)，d1=(2,0)，d2=(0,1)。q与d1方向一致，相似度1；q与d2正交，相似度0。这个二维例子只用于理解公式，不是实际语义模型。

零向量没有定义良好的余弦相似度，应拒绝或明确处理。维度不一致也不能直接比较。

最关键的业务限制：相似度0.85不代表答案正确概率85%。分数还受到模型、语料、切块与查询类型影响。阈值需要用标注样本校准，不能跨模型直接复用。

### 可独立运行的相似度代码〔原创〕

```python
import math

def cosine(a, b):
    if len(a) != len(b) or not a:
        raise ValueError("向量维度必须相同且非空")
    if any(not math.isfinite(x) for x in (*a, *b)):
        raise ValueError("向量包含非有限值")
    na = math.sqrt(sum(x * x for x in a))
    nb = math.sqrt(sum(x * x for x in b))
    if na == 0 or nb == 0:
        raise ValueError("零向量不可计算余弦相似度")
    score = sum(x * y for x, y in zip(a, b)) / (na * nb)
    return max(-1.0, min(1.0, score))
```

这里限制结果范围以处理微小浮点误差。代码用于小型教学数据，没有解决极端数值的溢出，也没有实现生产向量索引。

## 7. 精确扫描、近似索引与向量数据库

原课程把 JSON 索引加载进 DataFrame，再计算相似度。这适合观察每一步，但“存成表”并不自动获得高效近邻查询。

精确扫描对每个候选计算相似度，能得到所设度量下的精确排名；粗略计算工作量与 N×D 成正比，N为片段数量，D为维度。

近似近邻索引以部分准确性换取速度和资源收益。“近似召回率”衡量是否找到精确排名中的邻居；“语义相关召回率”衡量是否找到了人工认为相关的资料，两者不是同一指标。

向量数据库的工程价值还包括元数据过滤、增删改、持久化、并发与运维。即使数据库检索很快，应用仍要检查文档权限和资料版本。

## 8. 索引记录应保存什么〔工程补充〕

推荐至少保留：

```json
{
  "chunk_id": "example-chunk-001",
  "document_id": "example-metric-guide",
  "source_version": "example-commit",
  "text": "完整原文片段",
  "embedding_model": "example-model",
  "embedding_dimension": 3,
  "chunking_version": "example-v1",
  "valid_from": "2026-09-01",
  "access_group": "example-team"
}
```

这是元数据示例，未包含真实向量。

查询向量和文档向量必须使用兼容的模型与配置。维度相同只是必要检查之一；两种不同模型即使都是1024维，也通常不能放在同一空间直接比较。

升级 Embedding 模型通常需要重新生成文档向量。可以新建索引、离线回归、灰度切换，再回收旧索引。文档删除与权限撤销也要同步到索引，不只是删掉页面。

## 9. 混合检索与重排〔工程补充〕

常见流程是分别做关键词召回和向量召回，按 chunk_id 去重，再融合或重排。

不要直接把不同系统的原始分数相加：关键词分数与余弦分数的含义及范围不同。可以采用基于排名的融合，再通过标注评测选择参数。

重排是对候选相关性重新打分，不是再运行一次相同的余弦计算。重排也无法补救根本没有召回的资料。

租户与权限过滤应尽早施加。在只取少量候选后才过滤，可能导致合法相关资料没有机会进入结果；同时也不能把未授权原文发给重排模型或生成模型。

## 10. 如何知道搜索有效

先准备真实业务问题及人工标注的相关片段。每个问题可能有多个可接受片段。

- Recall@k：前k项召回了多少标注相关片段。
- MRR：首个相关结果的倒数排名，再对问题求平均。
- 重复率：结果是否被同一文档的重叠块占满。
- 无答案错误返回率：语料中没有答案时是否仍误推相关片段。
- 延迟与资源：按相同数据规模比较。

如果问题只有一个相关片段，排第1与排第10在Recall@10上都成功，但用户体验明显不同，所以需要同时看排名指标。

未知问题、精确ID、否定条件、中文缩写和口径冲突都应进入评测。改切块或模型后重新评测，不能只看几条演示截图。

## 11. 自查

- Embedding 能代替原文吗？不能，证据还需保留并获取原文。
- 为什么相似度不是置信度？它表示向量几何关系，不是经校准的答案正确概率。
- 所有向量都同维度就能混用吗？不能，必须在兼容空间中。
- 文档删除后只删原文件够吗？不够，还要处理索引和缓存。
