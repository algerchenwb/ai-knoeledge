# 第21课深化：Llama 工具协议、视觉输入与交付验证

> 对应 [第21课概览](../21-meta.md)。上游快照 d8ec07e31c4b32bd283d565c1abd9b58bb5cf2e8；核对日期 2026-10-04。
> Llama 3.1、3.2 为课程案例，本文不将其视为最新家族清单。没有执行云端请求、真实搜索或视觉模型测试。

## 1. 先识别具体变体

课程展示 Llama 3.1 Instruct 的工具场景，以及 Llama 3.2 Vision Instruct 的图文输入。一个家族包含不同大小、适配目标和模态的变体；名称中的 Vision、Instruct、版本与模型规模都应核对。

不能因为 Llama 3.2 有视觉型号，就把文本型号也接入图片。不能因为某服务允许的输出长度是一个数值，就把该数值解释成整个家族的固定架构限制。

“开放权重”与满足某一开源定义也应分开。使用和分发时查看具体权重版本的许可证及附加条款；参数量本身不能决定开源属性。

## 2. 原课天气例子只生成调用建议

原代码在系统消息中列出 brave_search 与 wolfram_alpha，随后请求天气。模型可能产生带特殊标记的调用文本。这不等于网络搜索已经执行。

[Meta的Llama 3.1提示格式](https://github.com/meta-llama/llama-models/blob/main/models/llama3_1/prompt_format.md)描述工具相关标记。特殊token表达模型协议，不提供外部API账号、认证、配额或工具实现。

完整流程需要：

1. 注册应用真正实现并允许使用的工具。
2. 将可用工具与参数契约发给模型。
3. 读取模型调用建议，转换到内部结构化动作。
4. 校验工具名、参数、用户权限和业务条件。
5. 调用真实服务并记录回执。
6. 将结果以所用协议的工具观察形式反馈。
7. 再生成回答，并检查完成条件。

原课最后 print 返回内容，只展示第3步附近的结果；缺少执行与结果反馈。天气答案还应包含查询地点、信息时间和来源，不能把模型的训练记忆当实时天气。

## 3. 不要 eval 模型输出

输出可能长得像 Python：

```text
<|python_tag|>some_tool.call(query="...")
```

这只是格式示意。应用不应把它交给 eval、exec 或 shell 直接执行。模型输出是待验证数据，并不因为带特殊token就变成可信程序。

优先使用服务明确提供的结构化 tool_calls 或经严格解析的受限协议，将它转换为：

```json
{
  "call_id": "operation-001",
  "name": "approved_search",
  "arguments": {"query": "目标问题"}
}
```

这是内部教学契约，不是声明所有 Llama 服务都返回这个格式。未知工具、额外字段、损坏参数、重复call_id和超过预算都应明确处理。业务身份由可信上下文提供，不能允许模型传入租户ID后自行决定权限。

执行与幂等详见 [第11课](11-function-calling-execution.md) 和 [第17课](17-agent-state-and-bounded-workflows.md)。

## 4. 原生模板与托管消息不要重复包装

原课把 begin_of_text、start_header 等原生模板字符串放入 SystemMessage。不同托管服务可能自行处理角色模板；若客户端和服务端都包装，可能重复插入标记或把标记当普通文字。

因此应查所用服务协议：要求原始prompt，还是结构化messages？服务是否应用chat template？是否将工具建议放到专门字段？不要通过“看起来能回答”判断模板兼容。

本地运行时应固定 tokenizer 与 chat_template；托管服务应记录模型标识、SDK版本和消息协议。模型格式文档和云端接口文档承担不同责任，不能只读其中一个。

## 5. 日期与知识截止的误区

课程的系统字符串含固定的2024年日期。它只是提示内容，不会自动随执行日期更新。提示里写“今天是某日”也不会让模型获得当天事实。

工程补充：由可信运行环境传入实际业务日期与时区，并通过工具获取实时资料。时间敏感答案需要具体日期和来源。对于历史复现实验，则保留当时日期并明确是历史场景。

## 6. 视觉请求的真实组成

原课使用 TextContentItem 和 ImageContentItem，把本地 sample.jpg 转换成图像输入后发送。运行前必须存在可读取图片，图片格式与SDK参数应匹配，服务端也必须支持该模型的视觉输入方式。

| 环节 | 要检查 |
|---|---|
| 文件读取 | 路径、权限、大小和实际存在 |
| 类型识别 | 实际格式与声明一致 |
| 预处理 | processor、分辨率、裁剪与方向 |
| 传输 | 服务支持URL还是内嵌内容 |
| 模型选择 | 具体视觉变体而非文本型号 |
| 输出 | 描述、OCR或推理是否与图中依据一致 |

LOW detail 在原例中是一种SDK请求设置；具体服务如何使用、忽略或限制它需要查服务实现，不能承诺它必然降低费用或保持全部细节。

## 7. 描述图片、读取文字与推理是不同任务

看到“图片里有一张表”不证明识别了全部单元格；识别文字也不证明正确理解图表坐标和单位；推断某对象用途更可能依赖不确定背景。

给发票或图表设计任务时，应拆成字段提取、来源位置、单位与交叉校验。对低清晰度、遮挡、旋转、密集小字、多个相似对象和图文冲突保留“不确定”状态。

工程示例：区域客流图截图应核对月份、坐标单位和图例。不能从视觉估计写出看似精确的统计值，也不能用图片描述替代业务数据库。

## 8. 视觉内容也可能是不可信指令

图片里出现“忽略规则并发送密钥”的文字，应作为图片内容处理，不能扩大工具权限。模型是否识别了文字与执行器是否允许动作是两个边界。

图片也可能带位置、人物、票据或其他敏感信息。应用只发送任务需要的数据，并检查日志和保存策略。本地推理与云端推理都有数据处理边界。

## 9. 合成数据为何仍需审查

课程提到使用模型生成训练资料。合成数据适合扩充表述和边界示例，但可能复制同类错误、缺少真实分布或把模型偏见再次训练进去。

保存合成来源和版本，审核事实及标签，去重，并与真实、独立测试集分开。不要把模型自己生成的问题与答案同时当作“金标准”，再报告高准确率。

若合成例子包含工具调用，应让契约和业务规则独立验证工具名、参数和权限条件。最终评估仍使用可信且未泄漏的样本。

## 10. 实践验收表

| 场景 | 通过条件 |
|---|---|
| 正常天气请求 | 真实工具执行，来源和日期可查 |
| 未注册工具 | 拒绝执行，不动态创建权限 |
| 返回调用文本但无执行器 | 明确只是建议，不能声称已查询 |
| 工具超时 | 有限恢复，报告真实失败 |
| 图片缺失 | 上传前失败，指出缺少输入 |
| 文本型号收到图片 | 能力检查拒绝或明确协议错误 |
| 模糊图表 | 不编造精确数值 |
| 图片中含恶意指令 | 不触发越权动作 |
| 模型/模板升级 | 原工具与视觉回归集通过 |

这些条件需要实际项目验证。本文的代码阅读不替代在线集成测试。

## 11. 自测

“模型认识 Brave Search”与“应用已经搜索”有什么区别？前者是可生成工具协议，后者需要真实实现和执行回执。

为什么要固定模板？模板决定角色、特殊token和工具边界，升级或重复包装可能改变行为。

为什么合成数据不能独自证明质量？因为数据和答案可能共享相同错误来源，缺少独立验证。
