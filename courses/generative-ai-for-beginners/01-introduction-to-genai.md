# 01 · 生成式 AI 与大语言模型

> 原课程解读与中文重写；标为「工程补充」的内容是额外实践，不是原仓库承诺。核对日期：2026-10-03。

## 一句话理解

生成式 AI 是从学习到的数据规律中生成新内容的系统。传统分类模型常回答“这是哪一类”，生成模型常回答“接下来怎样写”。LLM 是处理语言的模型类别，生成式 AI 还包括图像、音频等模型。

## 从规则到 Transformer

规则系统依赖人工写条件，例如看到“退款”就进入退款流程。机器学习用数据学习模式；神经网络由多层可训练计算构成；Transformer 用注意力机制处理文本中不同位置的联系。它更容易并行训练，也是许多现代语言模型的基础。

注意力可以类比阅读时回看上下文。例如“杯子放不进箱子，因为它太小”，理解“它”需要综合语境；模型计算不同 token 之间的关联，但这并不保证每次都能判断正确。

## LLM 怎样生成文本

1. Tokenizer 把文本切成 token，再映射为整数 ID。
2. Embedding 将 token ID 转成模型可以计算的向量。
3. 模型结合上下文计算下一个 token 的概率分布。
4. 解码策略选择 token，继续生成，直到停止条件触发。

“下一 token 预测”是自回归语言模型的生成机制描述；不能把它理解成只有简单词频统计。大量训练让模型学会丰富的语言、代码和任务模式，但生成机制并没有内置事实数据库的完整校验。

## Token、参数与上下文

Token 不是固定的一个汉字或一个单词，同一句话在不同 tokenizer 下长度可能不同。参数是训练中调整的数值；参数量越大不代表所有任务都更好。上下文窗口是一次推理可以处理的 token 预算，通常包含输入并受到输出预算约束，具体计数以接口为准。

对话历史不是永久记忆。若应用下次请求没有带上历史，也没有使用服务端会话状态，模型就没有那些信息。知识截止时间也不等于数据最后修改时间，更不保证所有截止日前事实都准确。

## 预训练、指令调优与推理〔概念补充〕

| 阶段 | 做什么 | 好理解的类比 |
| --- | --- | --- |
| 预训练 | 从大量数据学习通用规律 | 广泛阅读 |
| 指令调优与对齐 | 学习按要求回应及偏好 | 接受工作规范训练 |
| 推理 | 在现有权重下处理请求 | 当场完成任务 |

提示词与 RAG 通常改变请求上下文，不修改权重。微调会修改部分或全部可训练参数。三者作用不同，后续章节会分别展开。

## 为什么会幻觉

模型可能在信息不足时补出看似合理的内容，也可能把相似概念混淆。流畅、详细、语气肯定都不是事实证据。降低 temperature 能减少某些随机性，却不能修复缺少证据的问题；有些模型也不支持该参数。

temperature 控制采样分布的平滑程度，top_p 限制参与采样的累计概率范围。这些是解码控制，不是“智商按钮”。数学与统计结果应交给确定性代码或可信数据工具计算。

## 业务例子

“某商圈近三月客流上涨多少”至少需要月份、商圈定义、客流口径和真实数据。模型可理解问题、选择接口、组织解释；增长率交给代码计算。没有取到数据时，正确结果是说明缺项，而不是生成一个貌似合理的百分比。

## 练习

分别提出常识解释、当前数据查询、精确计算三类问题，记录哪些可直接生成、哪些需要检索、哪些应调用工具。自查：为什么一个答案格式正确仍可能事实错误？因为格式符合要求只验证结构，没有验证内容。
