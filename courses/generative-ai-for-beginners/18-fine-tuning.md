# 18 · 模型微调

> 原课程解读与中文重写；「工程补充」为额外实践。核对日期：2026-10-03。

## 微调改变的是什么

提示词和 RAG 通常改变输入，微调改变模型的可训练参数。可以把它类比为通过一批高质量示例训练稳定的工作习惯。它适合特定格式、风格、分类和任务行为，不应优先当作不断更新事实的存储方式。

原课建议先建立提示词与 RAG 基线，再衡量数据准备、训练、部署和评估成本。

## 三种训练目标

| 方法 | 信号 | 直观理解 |
| --- | --- | --- |
| SFT | 输入与期望输出 | 学正确示范 |
| 偏好训练，如 DPO | 更好与更差的输出对 | 学哪种回答更可取 |
| 强化式训练 | 可评价的奖励或反馈 | 优化任务反馈 |

这些是方法类别，供应商是否支持、支持哪些模型及参数，要查目标平台。不能从课程的一种服务实现推断所有微调都使用同一种底层技术。

## LoRA 与全量微调〔概念补充〕

全量微调调整大部分或全部权重，成本高；LoRA 在部分层加入低秩可训练矩阵，通常只训练较少参数。QLoRA 等方法结合量化降低资源压力，但并不意味着“任何硬件都可以训练任何模型”。

LoRA 是参数适配方法，SFT 是训练任务目标，两者可以组合，不属于互斥分类。

## 数据质量比数量口号重要

每条样本应有清楚输入、正确输出和业务来源。包含容易混淆的类别、缺项与拒绝回答案例。去掉互相矛盾标签、错误时间、无依据结论与泄露资料。输入所含上下文应接近真实上线场景。

~~~json
{
  "messages": [
    {"role": "system", "content": "提取查询参数，缺失项使用 null。"},
    {"role": "user", "content": "查询示例商场的工作人群画像"},
    {"role": "assistant", "content": "{\"region\":\"示例商场\",\"month\":null,\"population_type\":\"worker\"}"}
  ]
}
~~~

这是常见对话样本形态示意，实际上传格式取决于平台。不能把用户点赞日志不加审核直接拼成训练集。

## 训练集、验证集与测试集

训练集用于更新参数；验证集用于选配置；测试集用于最终比较，不能被调参过程反复泄露。按实体、来源或时间分组划分可减少相似样本跨集合泄漏。训练损失下降不等于业务成功率提升。

对 API Agent，测工具选择、参数准确率、缺项识别与越权拒绝；同时检查通用能力是否退化。只训练正确调用而没有不该调用的案例，会形成过度调用。

## 超参数怎样理解

Epoch 是训练数据被使用的轮次；learning rate 控制每次参数调整幅度；batch size 是一次优化步骤涉及的样本规模，具体还受梯度累积等影响。值越大不一定越好，过拟合可能表现为训练集好、未见过输入差。

## 何时不微调

数据每天更新、需要引用文档、缺少可用样本、基础提示词尚未验证，通常先改善检索、工具或流程。模型不支持目标能力时，也未必能靠少量微调补齐。

## 练习

为人口类型提取建立无歧义、歧义与缺项样本，先测 few-shot，再提出微调假设。只有在独立测试集证明收益、并算清训练和部署成本之后，才能判断值得做。
