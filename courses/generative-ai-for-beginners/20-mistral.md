# 20 · Mistral 模型案例

> 原课程解读与中文重写；「工程补充」为额外实践。核对日期：2026-10-03。

## 本课的定位

原课通过 Mistral Large 2 (2407)、Mistral Small 与 NeMo 展示同一家族中的能力、成本与部署差异。这些是明确版本的教学样例，不能把其中旗舰称号、价格降幅和可用性作为当前事实直接使用。

## 读模型家族要抓住什么

Large、Small 是系列定位；型号的具体参数、许可证、上下文、工具格式及部署方式必须查对应版本 model card。同一家族不保证统一架构，也不保证商用条款相同。

课程提到 NeMo 的 Tekken tokenizer，以及与其他 tokenizer 的比较。核心知识是“相同输入在不同 tokenizer 下长度不同”，而不是给所有 Mistral 模型套一个固定节省比例。

## 原课的 RAG 示例

文本切分后使用 Cohere embedding 建立 FAISS 向量索引，把问题编码并检索候选，再将片段和问题交给 Mistral 生成答案。Embedding 提供者与生成模型可以不同，关键是查询与文档的向量必须兼容。

FAISS 是近邻搜索库与索引工具，不应自动等同于带权限、备份和分布式管理能力的完整数据库。使用它时需要应用自己维护原文、元数据和版本。

## 多语言与 Tokenizer〔工程补充〕

中文、韩文、英文、代码在 tokenizer 下的长度与切分特征不同。实际要统计输入 token 与输出 token，并检查截断是否损伤关键资料。

token 更少可能降低某些计费或上下文压力，但费用还取决于单价、调用次数与输出长度。不能只看 token 数下结论说一定更便宜或更快。

## 大小模型怎么比较

用相同脱敏任务、相同资料和相同工具测 Small 与 Large，记录任务成功率、首输出与整体延迟、重试次数和成功任务成本。单次出现“快 3 秒”不能变成固定性能保证。

对简单分类，小模型可能足够；对复杂工具依赖和多来源冲突，需要真实测试。词数更多或表达更漂亮不是质量指标。

## 工具调用检查

模型应返回目标接口支持的工具结构，执行器再做白名单、schema、授权和结果回传。更换供应商时可能需要适配字段，而不是只替换 model 名。是否原生支持某种工具格式也应按具体版本确认。

## 课程中应谨慎理解的说法

试用或样例可调用不意味着长期免费；某个 NeMo 版本的 Apache-2.0 条款不代表同品牌所有型号都一样；性能百分比依赖特定评测集。知识库保留案例背景，选型时重新测量。

## 练习

选一段中文 API 文档，比较两个模型的 token 数、参数提取结果、工具格式与延迟。将模型、tokenizer revision 和生成配置一并记录，得到可复现结论。
