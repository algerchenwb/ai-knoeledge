# smolagents CodeAgent：用代码组合工具完成查询

核验日期：2026-10-04。证据级别：官方内存 SQLite 完整示例；本轮只运行独立 SQL 金标准，未调用模型。

## 1. 原始任务很小，机制很清楚

官方 text_to_sql.py 创建 receipts 表，插入四条虚构收据，暴露 sql_engine(query) 工具，再让 CodeAgent 找出金额最高的客户。最大的 price 是53.43，对应 Woodrow Wilson。这是可手算的金标准，非常适合作为第一条验证题。

它与普通“写代码助手”的差别在于：CodeAgent 将代码作为本轮行动形式，通过代码调用可用工具、处理结果，再回到反馈循环。生成代码不是最终交付物，完成用户的问题才是目标。

## 2. 工具说明是模型接触业务的接口

sql_engine 的文档字符串给出了表名、列名和输入要求，工具用 SQLAlchemy 执行传入 SQL 并返回字符串。CodeAgent 的 tools 列表只有这个工具，InferenceClientModel 提供模型调用。模型不需要接触数据库连接对象的构建细节。

工具描述应准确表达能查什么、什么参数必需、返回结果什么意思。“最贵收据”可以按 price 降序；“付款总额最大”却可能需要 price+tip。语义不同，即使两个 SQL 都合法，答案也不同。业务字段含义不能只靠列名猜测。

## 3. 代码组合为什么有价值

JSON 工具调用一次通常表达一个动作；代码可以把多个结果赋值、循环、筛选，再组织下一次调用。对于批量对象或需要确定性算术的任务，程序表达比自然语言反复描述更直接。

这不自动减少费用或提高准确率。一次代码动作中可以包含多次外部调用，必须同时统计模型步数与实际工具调用数。代码能更高效地放大正确计划，也能更高效地放大错误或越权行为。

## 4. 示例没有提供的生产保障

上游工具直接 con.execute(text(query))，没有在工具中实现只读 SQL 验证或业务权限检查。内存数据库是教学环境，不能照搬到生产数据库。README 描述了沙箱执行选项，但本例未声明启用这些隔离配置。

教学改造：数据库账号只读；工具限定表和租户；任务限制调用次数、扫描量和返回体积；金额用 Decimal 或定点类型，避免 Float 的精度问题。模型只选择合适工具，鉴权及配额由服务端执行。不要通过检查字符串是否含 DELETE 就宣称已经安全限制 SQL。

## 5. 适用于 API Agent 的改造

可以让模型调用“按对象批量获取画像”的受控工具，再用确定性函数计算合计和占比。批量接口能替代循环中重复发80次单对象请求，服务端提供部分失败结果和对象映射。

例如输入两个区域对象，返回每个对象的 data_version、population_type、value、status；代码只对同口径成功项计算，缺失项显式保留。参数 schema 限制批量数量，工具内部仍需完整验证身份与数据权限。这是本文工程设计，不是本例原有功能。

## 6. 复现与自测

[离线脚本](examples/agent_case_checks.py)用相同的四个姓名与金额核对 SQL 金标准，并检查 price 与 price+tip 的计算值。它没有安装 smolagents、没有执行模型生成代码，也不能证明模型能稳定选对 SQL。

正式复现需按来源提交创建隔离环境，准备所选模型的授权和调用预算，再运行官方 examples/text_to_sql.py。记录实际 SQL、工具输出和最终回答，重复多次检验语义稳定性。练习：为什么仅返回“Woodrow Wilson”仍可能不够？因为最好同时给出金额、排序字段和原始收据标识，便于验证。
