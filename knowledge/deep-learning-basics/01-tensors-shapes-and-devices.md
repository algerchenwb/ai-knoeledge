# 01｜张量、形状、数据类型与设备

> 目标：能读懂 [batch, features]，发现输入形状错误，区分逐元素乘法和矩阵乘法。

## 1. 张量是什么？

在这里，把张量理解成带有形状、数据类型和存储设备的多维数字数组即可。它保存模型输入、输出和参数。数学中的张量还有更严格的定义，本篇只讨论深度学习框架里的数据结构。

| 示例 | 形状 | 业务解释 |
| --- | --- | --- |
| 单个温度 | [] | 一个标量 |
| 一个地点的三个特征 | [3] | 客流、面积、业态编码等三个数值 |
| 四个地点各三个特征 | [4, 3] | 四条样本，每条三个输入 |
| 八张彩色图片 | [8, 3, 224, 224] | 批量、通道、高、宽 |
| 两段文字的向量序列 | [2, 10, 64] | 批量、序列长度、表示维度 |

这些轴的含义来自模型协议，不是张量自动知道的。一个 [4,3] 的数组可以表示四条样本，也可以表示三条样本的转置。数字没变，语义可能完全不同。

文字输入也不是直接把字符串塞进浮点矩阵：通常先分词成整数 token ID，再通过 Embedding 得到浮点表示。此处只是说明常见形状，不承诺所有模型采用相同布局。

## 2. shape、dtype、device 各管什么？

- shape：有多少个轴，每个轴长度是多少。
- dtype：每个元素怎样存储，例如浮点数还是整数。
- device：数据在哪个计算设备，例如 CPU 或 CUDA 设备。

```python
import torch

x = torch.tensor(
    [[1., 2., 3.], [4., 5., 6.]],
    dtype=torch.float32
)
print(x.shape, x.dtype, x.device)
```

此例应得到形状 [2,3]、float32、CPU。默认设备创建规则可受配置影响，本例假设没有修改全局默认设备。

dtype 不是装饰：模型权重通常是浮点类型，类别索引常用整数类型。把输入和权重放在不同设备，通常也无法直接做相同算子运算。排错先打印形状、类型和设备，往往比立即修改模型有效。

## 3. 逐元素乘法与矩阵乘法

设 A=[[1,2],[3,4]]，B=[[5,6],[7,8]]。

逐元素乘法 A*B=[[5,12],[21,32]]，对应位置分别相乘。

矩阵乘法 A@B=[[19,22],[43,50]]。第一个元素来自 1×5+2×7=19：A 的一行与 B 的一列做乘积求和。

对二维矩阵，[batch, input] @ [input, output] 得到 [batch, output]。内侧 input 必须匹配。

假设三条样本各有两个特征，输出四个分数：X=[3,2]，W=[2,4]，X@W=[3,4]。可加上形状 [4] 的偏置 b，为每一条样本加同一组输出偏置。这是广播的一个简单例子。

业务提醒：形状可广播不代表业务计算正确。预测 [N,1] 与标签 [N] 相减可能扩展为 [N,N]，把每个预测与所有标签比较，代码能够执行却改变了损失的含义。应显式统一成 [N,1] 或 [N]。

## 4. PyTorch 的 Linear 权重为什么看起来转置了？

nn.Linear(in_features=2, out_features=4) 的 weight 常见形状是 [4,2]，输入仍是 [batch,2]。框架计算等价于 X @ weight.T + bias。

这是存储约定差异。不要根据 weight 的形状擅自把输入转置。理解“输入最后一维必须匹配 in_features”更实用。

## 5. cat 与 stack

假设 a 和 b 都是 [2,3]：

| 操作 | 输出形状 | 含义 |
| --- | --- | --- |
| cat([a,b], dim=0) | [4,3] | 在已有样本轴连接 |
| cat([a,b], dim=1) | [2,6] | 在已有特征轴连接 |
| stack([a,b], dim=0) | [2,2,3] | 新增一个轴来容纳两组数据 |

cat 连接已有轴，其他轴必须匹配；stack 新增轴，各输入形状需要一致。把同一地点的“不同日期”合成序列时，应该先定义日期轴，不能随意 cat 后就把数据称为时序输入。

## 6. reshape 不会自动改变业务含义

把 [2,3] reshape 成 [3,2] 只是重排形状，不等于转置，也不会把“样本轴”和“特征轴”的语义互换。转置改变轴顺序；reshape 按元素排列规则改变形状。

图像 flatten 把每张图片展开成特征向量，例如 [batch,28,28] 变成 [batch,784]。这保留数值，但模型不再从形状上显式看到像素的二维位置；选择全连接网络还是卷积结构是另一层设计问题。

## 7. 从 NumPy 创建张量是否一定复制？

torch.from_numpy 对支持的 NumPy 数组通常共享 CPU 内存。更改数组可能更改张量；某些 CPU tensor.numpy() 转换也可能共享存储。

这有利于减少复制，但可能造成“后台缓存怎么被修改了”的意外。需要独立副本时应明确复制，而不是把转换函数当作复制保证。CUDA 张量要先移动到 CPU 才能按常见路径转为 NumPy；需要脱离梯度图时还要 detach。

同理，detach 是断开梯度关系，不是复制数据。避免用它作为“不可变快照”的替代。

## 8. 设备与内存的实际考虑

把大张量送 GPU 有传输成本。多次在循环里把同一数据来回搬运，可能抵消加速收益。模型与输入应放在兼容设备，预测后的必要结果再回传。

float32 每个元素通常占四字节。例如 [32,128,768] 的单个张量有 3,145,728 个元素，原始数据约 12 MiB。训练还需要参数、梯度、优化器状态和中间结果，这不是总显存估算。

原地操作常以 _ 结尾，例如 add_。它直接修改已有存储，可能干扰梯度计算所依赖的历史值。初学阶段先用非原地表达式，确认语义后再考虑节省内存。

## 9. 练习与答案

1. X=[8,5]，W=[5,2]，X@W 是什么形状？  
   答：[8,2]，每条样本产生两个输出。

2. 两个 [4,3] 张量 stack(dim=0) 与 cat(dim=0) 有什么区别？  
   答：分别是 [2,4,3] 与 [8,3]，前者新增轴，后者延长已有轴。

3. [N,1] 和 [N] 都含 N 个数，算损失前能不管形状吗？  
   答：不能，广播可能得到 [N,N]，必须核对轴语义。

4. detach 后修改张量一定不会影响原始张量吗？  
   答：不一定，detach 可能共享存储。需要独立快照时还要复制。
