# 类别编码与组合流水线：避免把城市编号学成大小关系

## 编号、次序与距离是三件事

把城市编码成汕头=0、深圳=1、广州=2，方便存储，但不表示广州是深圳的两倍，也不表示两城市差值有地理意义。对线性模型或距离模型，直接输入这个编号可能引入人为次序。

有真实等级的类别可以按明确业务顺序编码，例如服务等级。OrdinalEncoder 的默认类别排序未必符合业务等级，应明确配置并验证。LabelEncoder 主要用于目标标签，不宜把它误当作通用特征编码流水线。

## One-hot 把每个类别变成一列

训练城市为 [汕头,深圳,广州]，得到三列，每行只有对应一列为 1。类别词表在拟合时确定，线上要保持列含义和顺序，不能每个批次重新编码。

假设训练类别 [A,B]，handle_unknown='ignore' 时，新类别 C 输出 [0,0]。这保证接口可执行，却没有让模型学会 C 的真实特征。若同时 drop='first'，被丢弃的 A 也可能是 [0]，因此未知类别会与参考类别发生表示重合，应理解这种约定。

低频类别合并能控制维度，但训练频率阈值、未知与缺失的归属必须固定。缺失是一种状态，未知是词表外的新值，两者不应在业务说明中混为一谈。

## 高基数不只是“大一点”

若 POI ID 有几百万个，直接 one-hot 会扩大维度；ID 还可能让模型记住门店而不能泛化到新门店。需要先确定任务是预测已有门店未来，还是预测未见门店，两者应有不同验证设计。

可考虑低频归并、哈希、embedding 或 target encoding，但每种表示都有代价。哈希可能碰撞；embedding 需要训练与未见 ID 策略；目标编码使用标签统计，尤其容易泄漏。

## Target encoding 为什么训练和推理不一样

目标编码用某类别的目标均值表示它，常结合全局均值做平滑。每个类别只有一个样本时，未平滑的完整训练均值等于它自己的标签，模型等于看到了答案。

scikit-learn TargetEncoder 的 fit_transform 使用内部 cross fitting：每个训练折的编码来自其他折。其 fit(X,y).transform(X) 不等于 fit_transform(X,y)，这是有意的防过拟合设计。新数据 transform 则使用完整训练数据学到的映射，未见类别使用训练全局均值。

教学数据四个唯一类别 [a,b,c,d]、标签 [0,2,4,6]，两折、不洗牌、连续目标、smooth=0：完整映射得到 [0,2,4,6]；cross fitting 得到 [5,5,1,1]，因为每折的类别都没出现在另一折，只能退回另一折均值。

内部随机/普通交叉拟合未必匹配时间或门店分组限制。若任务有未来信息限制，要设计满足可用时间的编码，不能仅凭“内部 cross fitting”宣布时间泄漏已经解决。

## ColumnTransformer 与 Pipeline 分工

| 部件 | 作用 |
| --- | --- |
| 数值子流水线 | 填补、缩放指定数值列 |
| 类别子流水线 | 类别填补、one-hot 等 |
| ColumnTransformer | 按列选择子流程，合并结果 |
| 外层 Pipeline | 先处理，再拟合预测模型 |

一个门店输入可能包含客流、租金、城市、业态。应显式选择字段，不让临时调试列、目标列或不可上线字段通过 remainder='passthrough' 意外进入模型。保留输出 feature names 方便审计、解释和排查。

## 练习与来源

1. 未知城市能 transform 成全零，说明模型效果受保证吗？答：只保证编码约定可执行。
2. 目标编码必须把标签作为线上输入吗？答：不需要，线上用训练保存的映射。
3. 一套 Pipeline 能自动判断特征是否含未来答案吗？答：不能。
