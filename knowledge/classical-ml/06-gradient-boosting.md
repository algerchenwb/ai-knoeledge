# 06｜梯度提升树：后一棵树怎样补前面模型的不足？

> 先修：[决策树](04-decision-trees.md)、[梯度](../deep-learning-basics/02-autograd-and-backpropagation.md)。目标：区分 bagging 与 boosting，理解残差、负梯度、学习率和早停。

## 1. 森林与提升树的核心区别

随机森林通常独立训练多棵具有差异的树，再平均。梯度提升逐轮建立加法模型：新树根据当前模型的不足提供修正。

常见形式：

Fₘ(x)=Fₘ₋₁(x)+ηhₘ(x)。

F 是当前总预测分数，h 是新树贡献，η 是 learning_rate。它通常不是把所有树预测简单除以树数。

“修正错误”是类比；更准确地说，新树常拟合相对于当前预测的损失负梯度，再根据具体损失完成叶值更新。分类时它不是给前面分错的样本重新贴一个类别就结束。

## 2. 平方误差下的残差例子

用 L=0.5(y−F)²，损失对 F 的负梯度为 y−F，正好是残差。

训练标签 y=[10,20,30,40]，初始常数预测为均值 25。残差为 [−15,−5,5,15]。

假设深度 1 的新树按输入把前两条分一叶、后两条分另一叶。叶内平均残差为 −10 与 10。学习率 η=0.5 后，新预测是 [20,20,30,30]。

初始 MSE=125，新 MSE=50。它减少损失，却没有一次完全拟合。这是学习率收缩的直观效果，不是所有数据都按此数值变化。

## 3. 其他损失不一定等于普通残差

平方误差与残差关系很直接。二分类对数损失的负梯度与 y−p 有关，其中 p 是由当前分数映射出的概率。

绝对误差的梯度信息与符号有关，叶子可能再按中位数等方式更新。因此“所有 GBDT 都直接拟合 y−预测值”是过度简化。

分类提升的基学习器常是回归树，因为需要预测连续梯度或分数贡献，不是每轮只输出硬类别。

## 4. 学习率与树数量要一起看

| 改动 | 可能效果 | 不保证什么 |
| --- | --- | --- |
| 减小 learning_rate | 每棵树贡献更小，往往需更多轮 | 不保证固定树数下效果更好 |
| 增加 n_estimators | 增加修正轮数 | 不保证验证误差一直下降 |
| 增加树深 | 每轮能表达更复杂交互 | 不保证泛化更好 |
| 增加叶子最小样本 | 平滑局部拟合 | 不保证能抓住少数局部模式 |
| subsample<1 | 每轮用部分样本，增加随机性 | 不等于随机森林独立训练 |

learning_rate 是对新树贡献的收缩。它与神经网络参数更新步长有共同的优化直觉，但具体更新对象和实现不同，不应直接套用神经网络学习率数值。

## 5. 可运行的一轮提升核对

```python
import numpy as np
from sklearn.ensemble import GradientBoostingRegressor
from sklearn.metrics import mean_squared_error

X = np.array([[1.], [2.], [3.], [4.]])
y = np.array([10., 20., 30., 40.])
model = GradientBoostingRegressor(
    n_estimators=1, learning_rate=0.5,
    max_depth=1, loss="squared_error", random_state=42
).fit(X, y)
pred = model.predict(X)
print("initial", model.init_.predict(X))
print("after one stage", pred)
assert np.allclose(model.init_.predict(X), [25.]*4)
assert np.allclose(pred, [20., 20., 30., 30.])
assert np.isclose(mean_squared_error(y, pred), 50.)
```

这是训练机制核对。没有独立测试，所以不表示这个模型能预测实际地点未来客流。

## 6. 早停怎样保护验证边界？

可以在训练若干轮后检查独立验证误差，选择验证表现最好的轮数。停止依据是开发数据，不是最终测试集。

工程扩展：有显式时间/分组验证要求时，通用模型内部的随机 validation_fraction 不一定匹配业务边界。应检查实现是否允许正确的验证协议，或使用外部验证和阶段预测选择轮数。

合法流程是：开发训练集拟合候选轮数 → 开发验证集选择 → 固定方案 → 在开发数据上按既定规则重训 → 最终测试一次。不能把用于早停的数据同时宣称为从未参与选择的最终测试。

## 7. 直方图提升为什么更快？

HistGradientBoosting 将连续特征分桶，在桶统计上寻找分裂，减少逐节点处理全部精细取值的成本。它保留的是分桶后的候选切分，精度、速度和资源要一起权衡。

它与传统 GradientBoosting 是不同实现，不是仅换一个类名且所有参数完全相同。轮数常用 max_iter，而传统实现常用 n_estimators。类别、缺失值和单调约束支持也要按具体类与版本核对。

XGBoost、LightGBM、CatBoost 都属于相关生态，但结构、求解、类别处理和 API 有差异。本篇仅对已经读取的 scikit-learn 实现作具体解释，不把结论无条件推广到所有库。

## 8. 公平比较模型的最小协议

下面是业务实验方法，不是性能保证：

1. 明确目标：已有地点未来，还是新地点泛化。
2. 固定开发与最终测试边界，选择匹配的时间/分组验证。
3. 在同一开发数据比较线性基线、单树、森林和提升模型。
4. 分类看适合正类的指标与成本；回归看 MAE/RMSE、分层误差和简单预测基线。
5. 记录训练时间、模型大小与推理成本，使用相近资源预算。
6. 用验证结果固定方案，然后独立报告最终测试结果。

复杂模型训练更久、调参尝试更多，也更容易从选择过程获得优势。需要记录尝试预算，不能只比较各自挑出的单个最高分。

## 9. 提升树能解决哪些问题，不能解决哪些？

它善于表达非线性特征关系和交互，是结构化表格任务的常用候选。但它不能自动知道字段单位、发现所有未来泄漏，也不能证明因果规律。

普通常数叶树组成的模型仍有外推限制。若未来客流规模超出训练范围，不能认为“叠加很多树”就能合理延长增长趋势。

训练误差下降、验证误差上升时，应检查复杂度与数据协议；不要只加树直到训练误差归零。

## 10. 练习与答案

1. 随机森林和提升树都用很多树，为何不能当同一种模型？  
   答：前者通常独立随机化后平均，后者顺序优化加法模型。

2. 平方误差下负梯度为什么像残差？  
   答：对 0.5(y−F)² 求 F 导数是 F−y，取负即 y−F。

3. 一轮提升中的树一定是分类树吗？  
   答：不是，分类 GBDT 也常用回归树拟合连续修正信号。

4. 内部随机早停是否天然满足“预测未来的新 POI”？  
   答：不能，需要显式检查时间与地点隔离要求。
