# 07 聚类稳定性：ARI、标签比较与重采样实验

> 目标：能比较两次分组而不受簇编号影响；会手算 ARI；知道重采样稳定性和“业务正确”之间的区别。
>
> 前置：[K-means](01-kmeans-and-cluster-evaluation.md)、[层次聚类](05-hierarchical-clustering.md)、[OPTICS 与 HDBSCAN](06-optics-and-hdbscan.md)。

## 1. 同一算法再跑一次，为什么标签会变

两次分组可能都把前三个用户放在一起、后三个用户放在一起，但标签分别是：

~~~text
第一次：[0, 0, 0, 1, 1, 1]
第二次：[9, 9, 9, 7, 7, 7]
~~~

数字不同，分组关系完全相同。逐行比较数字得到 0%“准确率”，显然不合适。

先问自己在比较什么：

| 比较对象 | 需要的信息 | 能说明什么 |
| --- | --- | --- |
| 聚类与真实业务标签 | 相同对象及外部参考标签 | 分组与该标签的关联/一致性 |
| 两次算法结果 | 相同对象的两套分组 | 两套划分的一致性 |
| 重采样后的结果 | 对象 ID、采样记录、共同对象 | 对指定数据扰动的稳定程度 |
| 聚类的业务效果 | 实际行动及独立验证 | 是否帮助业务决策 |

ARI、AMI 可以比较两套划分；不要求其中一套一定是真实标签。API 名称 labels_true 并不自动赋予输入真值身份。

簇编号无需先按大小排序或人工配对；这些指标本身忽略编号置换。展示跨版本群体名称时，仍可能需要另行对齐，但那是不同任务。

## 2. Rand Index：比较样本对的关系

从 n 个共同对象中选择两个，共有 n(n−1)/2 对。

每对有两种问题：第一次是否同簇，第二次是否同簇？

- 两次都同簇：关系一致。
- 两次都不同簇：关系一致。
- 一次同簇、一次不同：关系不一致。

普通 Rand Index（RI）是“一致的对数 / 全部对数”。它避免了编号的问题，但当簇很多时，大量点对本来就不同簇，偶然一致也可能很多。因此常使用经过随机机会校正的 ARI。

“调整随机机会”不是给每次随机实验都强制返回 0。它是在特定随机划分模型与给定簇规模条件下校正期望一致性。

## 3. ARI 手算：从列联表开始

两套标签：

~~~text
U = [0, 0, 0, 1, 1, 1]
V = [0, 0, 1, 1, 1, 1]
~~~

按 U 的簇作行、V 的簇作列，表格记录交集数量：

|  | V簇0 | V簇1 | 行和 |
| --- | ---: | ---: | ---: |
| U簇0 | 2 | 1 | 3 |
| U簇1 | 0 | 3 | 3 |
| 列和 | 2 | 4 | 6 |

令 C(q,2)=q(q−1)/2：

- S = 各单元格 C(nᵢⱼ,2) 之和 = 1+0+0+3=4：两次都同簇的点对数。
- A = 各行和 C(aᵢ,2) 之和 = 3+3=6。
- B = 各列和 C(bⱼ,2) 之和 = 1+6=7。
- T = C(n,2)=15。
- 校正的期望 E=A×B/T=2.8。

$$
ARI=\frac{S-E}{(A+B)/2-E}
=\frac{4-2.8}{6.5-2.8}
=\frac{12}{37}\approx0.324324
$$

它不是“32.43% 用户分对了”，而是机会校正后的两套关系一致性。

解释边界：

- ARI=1：两个划分相同，允许编号变化。
- 随机、独立的划分在机会模型下平均接近 0；一次样本可以正，也可以负。
- 负值：一致性低于该随机基准，不是“负准确率”。
- n 太小或某些退化划分会让手算分母为零。库有专门约定，不能简单用普通公式除以零。

脚本核验 [0,0,1,1] 与 [0,1,0,1] 的 ARI 为 −0.5，并核验两次全体一簇时返回 1。

## 4. AMI、NMI 与纯度方向

互信息（MI）衡量知道一套标签后，对另一套标签减少了多少不确定性。AMI 将随机期望的 MI 扣除；NMI 归一化 MI，但没有同样的机会校正。

| 指标 | 编号置换不变 | 对称 | 机会校正 | 常用解释 |
| --- | --- | --- | --- | --- |
| ARI | 是 | 是 | 是 | 样本对关系一致性 |
| AMI | 是 | 是 | 是 | 标签信息的一致性 |
| NMI | 是 | 是 | 否 | 归一化的共享信息 |
| homogeneity | 是 | 否 | 否 | 每个预测簇是否只含一个参考类别 |
| completeness | 是 | 否 | 否 | 一个参考类别是否集中在一个预测簇 |

homogeneity 和 completeness 依赖“参考”和“预测”的方向：

- 把每个样本单独分簇，簇内都很纯，homogeneity 可为 1；但同类被拆碎，completeness 往往低。
- 把所有样本合成一个簇，同一参考类不会被拆开，completeness 可为 1；若参考标签含多类，homogeneity 会低。

V-measure 综合二者，默认是调和平均。不能只挑一个有利方向报告。

NMI/AMI 的归一化平均方式也应记录，尤其跨代码比较时。指标值接近不等于评价同一个统计对象。本篇完整手算的是 ARI，AMI 只验证相同划分下的编号不变性，没有独立重实现其随机期望计算。

## 5. 噪声标签也是一个“普通标签”

scikit-learn 的 ARI/AMI 不知道 −1 代表噪声，只把它当成一个标签值。

~~~text
U = [0, 0, -1, -1, 1, 1]
V = [0, 0,  2,  2, 1, 1]
~~~

两者 ARI=1，因为各对关系一致。指标不知道第一次中间两点只是“都未分配”，第二次却是明确的一个簇。

这可能很重要：很多噪声点会被当作同一大组，影响对一致性的判断。

应预先定义统计口径，例如：

1. 在全部共同对象上比较，把“同为噪声”作为同一标签关系，并明确这层含义。
2. 仅比较两次都成功分配的共同对象，再同时报告保留比例、每次噪声比例及成员变化。

第二种更容易得到好看的分数，因为困难样本被去掉。本例两次都分配的比例为 4/6≈66.67%，过滤后 ARI 仍为 1；不能把它写成“全部对象 100% 分组稳定”。

全体对象两次都标噪声，也可能得到 ARI=1。它证明了拒绝模式一致，不证明成功发现群体。HDBSCAN 的 −2、−3 无效行还应在比较前单独统计。

把每个噪声点都视为独立单例是另一种可能口径，会改变点对关系，不能悄悄替换计算方式。无论选哪种，都应写清楚。

## 6. 稳定性实验要先定义扰动

“稳定”必须相对于某种改变：

| 扰动 | 想检验的因素 | 应尽量固定什么 |
| --- | --- | --- |
| 同数据、换随机种子 | 初始化影响 | 数据、表示、参数、环境 |
| 无放回抽样 | 样本组成影响 | 抽样方案及候选参数 |
| 特征加测量噪声 | 测量误差影响 | 噪声大小与分布 |
| 更换时间窗口 | 时间变化 | 特征定义、样本身份与窗口规则 |
| 改尺度/距离 | 建模假设影响 | 评价对象及业务目标 |

如果同时换采样、种子、参数、特征，很难知道不稳定的来源。本篇示例固定特征和 K 候选，改变子样本与种子；因此观察到的是**两种变化的综合影响**，不是单独隔离的采样效应。

Bootstrap 是有放回抽样，可能重复同一对象，改变密度和权重。普通子采样是无放回抽样。本篇使用后者，不把它叫 Bootstrap。若使用有放回抽样，必须定义重复 ID 在比较时如何处理。

## 7. 共同对象的 ID 必须对齐

第一个子样本包含用户 [A,B,D]，第二个包含 [B,C,D]，只能直接比较共同的 B 和 D。两组 labels_ 的第一行分别属于 A 和 B，不能按行位置直接比较。

脚本使用原始行索引作为人工对象 ID：

~~~python
common, left, right = np.intersect1d(
    ids_i, ids_j, return_indices=True
)
assert np.array_equal(ids_i[left], ids_j[right])

score = adjusted_rand_score(
    labels_i[left], labels_j[right]
)
~~~

每个子样本 ID 唯一，labels_i 与 ids_i 的顺序一致。真实业务里应使用稳定、去重的对象标识；先验证 ID 语义，再计算分数。

共同对象过少时，分数会非常不稳定，甚至被退化情况主导。应制定最低交集样本量和群体覆盖规则，记录跳过了多少比较。本例交集为 147–161，且所有比较都被纳入。

有些模型可在固定锚点集上 predict，再比较锚点分组，这避免了交集变化，但测量的是模型对锚点的归属稳定。层次聚类、scikit-learn OPTICS/HDBSCAN 没有原生 predict，不能不说明就套用最近中心规则。两种协议不必得到相同结论。

## 8. 已运行实验：20 次子采样，三个 K

构造 240 个二维样本，生成中心为 [−4,0]、[0,4]、[4,0]，每团标准差为 1.5。生成种子 42。

协议：

- 用 NumPy 种子 2026，抽取 20 个子样本。
- 每次无放回抽取 192 个样本，即 80%。
- 对每个 K∈{2,3,4}，使用同一组子样本；模型 n_init=10，random_state 为 0…19。
- 两两比较 20 次结果，共 C(20,2)=190 对；每对在共同对象上计算 ARI。
- 不读取合成标签来选择分组，没有业务标签性能评估。

| K | 比较对数 | 交集范围 | ARI 中位数 | 10%分位 | 90%分位 |
| --- | ---: | --- | ---: | ---: | ---: |
| 2 | 190 | 147–161 | 0.974835 | 0.831970 | 1.000000 |
| 3 | 190 | 147–161 | 1.000000 | 0.980605 | 1.000000 |
| 4 | 190 | 147–161 | 0.703283 | 0.610379 | 1.000000 |

K=3 在本次协议下很稳定，K=4 的细分更容易变化。K=2 也相当稳定，但它把合成的三个生成群体概括为两个分组，说明稳定性无法独立证明正确粒度。

这是 60 次 KMeans.fit、合计 600 次初始化、570 次划分比较。配套脚本包含所有生成与对齐步骤。

## 9. 这些分位数不是置信区间

同一次拟合参与了很多点对比较：比如运行 0 同时出现在 (0,1)、(0,2) 等对中。所以 190 个 ARI 不独立。

表中的 10%和90%分位只是本次比较值的经验分位数：

- 不是“80% 置信区间”。
- 不是未来重新采样必然落在此范围的概率保证。
- 不是 190 次独立实验的样本量。
- 不包括真实数据采集偏差、模型类别选择或环境变化的不确定性。

更正式的推断需要专门设计独立重复单位及适当的统计方法。本文没有做这类置信区间推断，也没有简单把标准差除以 √190 来冒充标准误。

## 10. 稳定但没有用的三种结果

1. 永远所有点一簇：重新采样也一样，稳定，却可能没有细分能力。
2. 永远每点单独一簇：在共同对象上划分仍一致，却可能只是记住个体。
3. 永远依赖一个数据采集字段分组：稳定地反映数据来源，未必反映用户需求。

因此应同时检查：

- 非噪声覆盖、簇数量、大小分布。
- 选定距离下的内部几何指标。
- 与外部参考标签的关系（如果存在且符合业务目标）。
- 重采样/时间变化下的稳定性。
- 分组是否支撑可执行的策略与独立效果验证。

如果用稳定性来挑 K 或其他参数，那么这套实验就是开发选型过程。不要在同一实验上反复调到好看，再声称已经通过独立验证；最终评估方案需要预先保留或重新设计。

## 11. 练习与答案

1. 两次标签逐行不同但分组完全相同，ARI 是多少？  
   **答案：** 1，簇编号变化不影响结果。

2. ARI=0.32 是不是 32% 用户分类正确？  
   **答案：** 不是，它比较点对关系，且作了机会校正。

3. 重采样后两个 labels_ 长度相同，可以直接比较吗？  
   **答案：** 不够，必须确保每个位置对应相同对象，通常先按 ID 取交集并对齐。

4. 删除噪声后 ARI=1，可以只报告这个数字吗？  
   **答案：** 不应，必须同时报告筛选口径、覆盖比例及噪声变化。

5. 20 次运行得 190 对 ARI，可以当作 190 个独立重复吗？  
   **答案：** 不能，各比较共享拟合运行，存在依赖。
