# 03｜准确率、Precision、Recall、F1、AUC：模型分数该怎么看？

> 先修：[公平切分与交叉验证](02-validation-and-cross-validation.md)。目标：从业务代价选择指标，能手算一个混淆矩阵，并区分排名、概率和决策。

## 1. 99% 准确率为什么可能毫无帮助？

假设 1000 个样本里，990 个正常、10 个异常。一个模型永远回答“正常”，准确率为 99%，却找不到任何异常。

准确率回答的是“总共答对多少”，不是“重要的那类找到了多少”。因此先定义正类，再看错误类型。本篇的正类表示“需要关注的异常”；正类不是道德意义上的好，也不一定是数量较多的类别。

## 2. 混淆矩阵：先把四种情况数清楚

设模型对 1000 条样本做判断，实际异常 100 条、正常 900 条：

| 实际 / 预测 | 预测异常 | 预测正常 | 合计 |
| --- | --- | --- | --- |
| 实际异常 | TP=80 | FN=20 | 100 |
| 实际正常 | FP=40 | TN=860 | 900 |

- TP：真的异常，成功发现。
- FN：真的异常，但漏掉了。
- FP：正常，却误报异常。
- TN：正常，正确放行。

scikit-learn 在标签顺序 [0, 1] 时，confusion_matrix 返回的是 [[TN, FP], [FN, TP]]，与上面把正类放第一行的业务展示顺序不同。读取矩阵必须先确认 labels。

## 3. 四个常见指标的分母不同

| 指标 | 公式 | 上例 | 回答的问题 |
| --- | --- | --- | --- |
| Accuracy | (TP+TN)/全部 | 940/1000=94% | 全部样本答对多少？ |
| Precision | TP/(TP+FP) | 80/120≈66.7% | 报出来的异常里多少是真的？ |
| Recall | TP/(TP+FN) | 80/100=80% | 所有真实异常中找到多少？ |
| F1 | 2PR/(P+R) | 160/220≈72.7% | 查准与查全的调和平均是多少？ |

Precision 常叫精确率或查准率，Recall 常叫召回率或查全率。把 Precision 翻译为“准确率”容易与 Accuracy 混淆，报告时最好写英文名与分母。

F1 不使用 TN。它也没有直接代入误报和漏报的金额成本，所以 F1 高不代表一定最赚钱或风险最低。当模型没有预测任何正类时，Precision 的分母为零；用库函数时应明确零分母处理，并同时报告原始计数，不能把约定值当成证据。

Balanced Accuracy 在二分类下是正类召回率与负类召回率的平均。本例为 (80/100 + 860/900)/2≈87.8%。它减少多数类对总体准确率的支配，但仍不等于业务成本指标。

## 4. 改阈值，改变的是决策

模型可能输出分数 0.2、0.6、0.9。用阈值 0.5，大于等于 0.5 就判异常；换成 0.8，只把最高分样本报出。

对于固定分数集合，降低阈值会让预测正类集合扩大，TP 和 FP 不减，召回率不减；但 Precision 不保证严格下降或单调，因为新加入样本的真实标签分布会变化。

阈值不是模型权重，也不是默认 0.5 就合理。应该在验证集或适当的交叉验证流程中选择，确定后再做最终测试。业务可以选择“召回率至少 90% 时精确率最高”或者“每日最多审核 50 条时找到最多异常”。

如果人工审核能力只够前 50 条，Precision@50、Recall@50 和实际审核成本可能比默认阈值下的 F1 更贴近目标。

## 5. 用错误成本选方案

以下是虚构成本，不代表任何业务的真实价格：

- 每次误报额外消耗 10 元审核成本。
- 每次漏报造成 200 元损失。

上例的错误成本为 40×10 + 20×200 = 4400 元。另一个阈值如果得到 FP=100、FN=5，成本为 100×10 + 5×200 = 2000 元。误报更多却可能总损失更少。

实际还可能有每条告警固定审核成本、异常损失严重程度、预算、人工处理效果等约束。成本不确定时，应比较多组成本假设，而不是把一个虚构数字当作永久阈值依据。

## 6. ROC-AUC 与 AP 为什么不等于准确率？

Accuracy、Precision、Recall、F1 通常在确定阈值后衡量分类结果。ROC-AUC 和 AP 通常使用连续分数，考察不同阈值下的排序表现。

### ROC-AUC

ROC 横轴是 FPR=FP/(FP+TN)，纵轴是 TPR=Recall。AUC 是曲线下的面积。二分类下可理解为随机取一正一负样本，正样本得分更高的概率，并对并列分数计半分。

AUC=0.9 不是“90% 样本答对”，也不保证选定阈值时召回率高，更不保证分数就是可信概率。

类别极不平衡时，FPR 看似很小，绝对误报仍可能很多。例如正常样本一百万，FPR=1% 就约一万条误报。

### PR 曲线与 Average Precision

PR 曲线展示 Precision 与 Recall 的关系。AP 通过各召回增量对应的 Precision 加权汇总，scikit-learn 的 average_precision_score 使用非插值形式。不要把它与对 PR 点做梯形积分得到的 PR-AUC 无条件混为一谈。

正例很少时，PR/AP 更直接反映报出的结果有多可靠。随机无信息排序的参考水平大致与正类占比有关；具体有限样本分数会波动。不同正例比例的数据上，AP 不宜脱离数据分布直接比较。

## 7. 排名好，概率就准吗？

不一定。某模型把异常排在前面，AUC 很好；但所有分数都报到 0.99，实际异常比例远没有那么高，它的概率就可能不可信。

概率校准检查的是：预测约 0.8 的一组样本，实际正类比例是否也接近 80%。Brier score、log loss 可以评估概率预测质量，但一个汇总分数不替代校准曲线和分组检查。

判断模型要分三层：

| 层次 | 关注什么 | 常见评估 |
| --- | --- | --- |
| 排序 | 高风险是否排前面 | ROC-AUC、AP |
| 概率 | 分数是否对应真实发生频率 | Log loss、Brier、校准检查 |
| 决策 | 阈值后的行为是否合算 | Precision、Recall、成本、容量 |

## 8. 多分类的 macro、micro、weighted

假设有三个类别，样本量为 900、90、10：

- macro：先分别算每类指标，再等权平均。少数类同样有发言权。
- weighted：按各类真实样本量加权。多数类可能掩盖小类失败。
- micro：先汇总各类 TP、FP、FN，再算指标。标准单标签多分类且包含所有类别时，micro Precision、Recall、F1 与 Accuracy 相等。

weighted F1 是各类 F1 的加权平均，不是把 weighted Precision 和 weighted Recall 再代入 F1 公式。报告时应同时给出每类指标与 support（真实样本量）。

## 9. 回归任务看 MAE、RMSE、R²

客流预测通常是预测数值。令误差 e=预测值−真实值：

| 指标 | 含义 | 单位和注意事项 |
| --- | --- | --- |
| MAE | 绝对误差的平均 | 与目标同单位；容易解释 |
| MSE | 平方误差的平均 | 单位被平方；大误差影响更重 |
| RMSE | MSE 的平方根 | 与目标同单位；仍重视大误差 |
| R² | 相对测试集均值常数预测的改善 | 通常不大于 1；可以为负 |

若真实值 [10,20,30]，预测 [12,18,39]，绝对误差是 [2,2,9]：MAE=13/3≈4.33，MSE=89/3≈29.67，RMSE≈5.45。真实值均值为 20，标签总平方偏差为 200，因此 R²=1−89/200=0.555。

R²=0.555 不是“准确率 55.5%”。R² 为负表示比该测试集均值常数基准还差；真实值恒定时存在特殊定义/库处理，应查实现。

业务还应与“上周同一天”“最近几天均值”等可上线的基线比较。大商场和小店客流量级不同，可以同时报告总体绝对误差、规模分层误差。MAPE 遇到真实值接近零时会变得极大，库用很小的分母避免除零也不让它自动变得有意义。

## 10. 一个能手算核对的示例

```python
from sklearn.metrics import (
    confusion_matrix, accuracy_score, precision_score, recall_score, f1_score
)
y_true = [1]*100 + [0]*900
y_pred = [1]*80 + [0]*20 + [1]*40 + [0]*860
print(confusion_matrix(y_true, y_pred, labels=[0, 1]))
print("accuracy", accuracy_score(y_true, y_pred))
print("precision", precision_score(y_true, y_pred, zero_division=0))
print("recall", recall_score(y_true, y_pred, zero_division=0))
print("f1", f1_score(y_true, y_pred, zero_division=0))
```

预期矩阵 [[860,40],[20,80]]，其余输出约为 0.94、0.6667、0.8、0.7273。使用 AUC/AP 时应传原始分数或概率，不要只传已经截断的 0/1 分类结果来评估完整排序能力。

## 11. 练习与参考答案

1. 实际异常 100 个，报出 10 个且全是真的，Precision 和 Recall？  
   答：100% 和 10%，说明查准很高但漏掉很多。

2. AUC 高，线上审核团队仍不满意，应该看什么？  
   答：工作阈值、前 K 条的准确程度、每日告警数量、漏报损失和概率校准。

3. 能用最终测试集挑最好的阈值再汇报测试分吗？  
   答：不能把这样的分数继续称为独立最终评估；阈值选择应在开发阶段完成。

4. 两次 AP 不同能直接说模型退化吗？  
   答：先看样本来源、正类占比、标签和切分是否一致，再用同一数据比较。
 
## 12. 与生成式 AI 评估的联系

以上指标主要针对具有标签或数值答案的监督学习任务。不能直接用分类 Accuracy 概括自由文本回答质量。RAG 检索可定义相关文档标签并评估 Recall@K；生成答案则还需单独检查事实依据、引用正确性、业务完成度等。测试集隔离、指标定义和错误成本的原则仍然适用。
