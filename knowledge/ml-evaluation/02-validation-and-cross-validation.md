# 02｜训练、验证、测试与交叉验证：怎样公平比较模型？

> 先修：[数据泄漏](01-data-leakage-and-pipelines.md)。目标：根据“预测谁、预测什么时候”选择切分方式。

## 1. 三种数据的分工

| 数据 | 用来做什么 | 可以据此选择模型吗？ |
| --- | --- | --- |
| 训练集 | 学习模型权重、预处理参数 | 可以 |
| 验证集 / 交叉验证的验证折 | 比较模型、超参数、特征和阈值 | 可以 |
| 最终测试集 | 在方案确定后估计表现 | 不应反复用它指导修改 |

参数是训练算法学到的值，如线性模型的系数。超参数是外部设置，如正则化强度、树深、学习率。为了挑出超参数而比较分数，本身也属于学习和选择过程。

不存在通用的 8:1:1 最优比例。少数正例、时间跨度、地点数量和上线目标比比例更重要。测试集只有几个正例，哪怕占 20%，指标也可能非常不稳定。

## 2. K 折交叉验证到底做了什么？

假设开发数据分为 A、B、C、D、E 五份：

| 轮次 | 用来训练 | 用来验证 |
| --- | --- | --- |
| 1 | B、C、D、E | A |
| 2 | A、C、D、E | B |
| 3 | A、B、D、E | C |
| 4 | A、B、C、E | D |
| 5 | A、B、C、D | E |

每轮都重新训练一个模型，预处理也重新学习。最后报告五个验证分数及其平均值。它不是训练一个模型再反复测五次，也不是把验证结果继续用于当前折的梯度训练。

通常先单独保留最终测试集，再对开发数据交叉验证。选好方案后，用全部开发数据重新训练一个最终模型，再测最终测试集。

代价也很直接：五折通常意味着约五次训练；若比较 20 组设置，就可能约 100 次拟合，最后还可能重训一次。交叉验证改善数据使用与比较方法，不会凭空创造新的独立样本。

## 3. 为什么平均值还不够？

某方案五折分数为 0.90、0.90、0.89、0.91、0.50。平均值约 0.82，但最后一折显著下降，需要查是否发生地区差异、时间漂移、标签错误或小样本问题。

可以报告均值、标准差、每折样本量和类别数量。但折间训练数据重叠，分数并非相互独立；“均值 ± 标准差”不是自动得到的统计置信区间，也不能只凭均值差 0.01 就宣称某模型一定更好。

业务补充：比较两个模型应尽量使用相同切分，让难易程度保持一致，另看误差是否集中在关键业务对象上。

## 4. 根据任务选切分器

| 上线问题 | 常用方法 | 能保护什么 | 仍需注意 |
| --- | --- | --- | --- |
| 独立样本二分类，类别比例不均 | StratifiedKFold | 尽量保持各折类别比例 | 不自动隔离用户或时间 |
| 相对独立的回归样本 | KFold | 每份轮流验证 | 顺序本身有意义时慎用 |
| 预测没见过的 POI / 用户 | GroupKFold | 同一组不跨训练和验证 | 分组数、组大小和分布 |
| 组隔离且类别比例也重要 | StratifiedGroupKFold | 尝试兼顾两个约束 | 不保证完美平衡 |
| 用历史预测未来 | TimeSeriesSplit / 自定义时间切分 | 训练在过去，验证在后来 | 标签成熟时间、间隔和面板结构 |

“分层”解决类别配比，“分组”解决对象隔离，“按时间”解决未来评估。它们保护的边界不同。

## 5. POI 客流数据为什么不能直接按行随机切？

假设每行是一个 POI 的一天，共有 100 个地点、90 天记录，约 9000 行。行数大不意味着有 9000 个独立对象。

如果目标是已有门店未来客流，应该用较早日期训练、较晚日期验证。若用随机切分，训练可能包含验证日期之后的数据，掩盖时间变化。

如果目标是新地点预测，应该留出整批 POI。同一地点在两边，可能变成“认识该地点之后猜另一条记录”。

如果目标是未来的新地点，则必须同时满足对象和时间限制。例如训练用旧地点较早记录，验证用留出的地点较晚记录。这是业务自定义切分，单个通用切分器通常不够。

## 6. TimeSeriesSplit 的实际边界

它按输入顺序和样本索引切分，使用前面的记录训练，后面的记录验证。输入必须正确排序。

- 等间隔单序列更容易保证各验证折覆盖相同时间长度。
- 多 POI 面板表里，同一天有很多行；按行切分可能把同一天拆到两边。应先按日期划分，再映射到全部行。
- gap 以行数计，不是天然的天数。不同日期行数不同时，不能把 gap=7 当作隔离七天。
- 训练标签应在验证预测时点前成熟。例如预测未来 30 天总量，不能在 5 月 1 日模拟预测时使用直到 5 月底才完整知道的训练标签。
- 正确使用过去观测并不要求无差别删除所有重叠历史窗口；需要隔离的是不该提前知道的信息，以及会让评估目标失真的依赖。

这些面板与标签可用性说明是工程扩展，不是通用切分器自动实现的保证。

## 7. 一个可运行的五折评估示例

这是独立合成数据示例，假设样本近似独立：

```python
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split, StratifiedKFold, cross_validate
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

X, y = make_classification(
    n_samples=800, n_features=10, weights=[0.85, 0.15],
    n_informative=5, random_state=42
)
X_dev, X_test, y_dev, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=42
)
model = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
result = cross_validate(
    model, X_dev, y_dev, cv=cv,
    scoring={"ap": "average_precision", "balanced": "balanced_accuracy"}
)
for name in ("test_ap", "test_balanced"):
    values = result[name]
    print(name, values, values.mean(), values.std())
# 完成模型/特征/阈值选择后才使用 X_test、y_test 做最终评估。
```

注意这些函数返回的键叫 test_ap，但这里的 test 指“每折的留出部分”，不是单独保留的最终测试集。不要被变量名误导。

## 8. 嵌套交叉验证是什么？

不断根据某组交叉验证结果挑模型，会对这组验证数据产生选择偏差。嵌套交叉验证用内层挑方案、外层估计整套选择流程的表现。

外层每次留出一份；剩余数据进入内层交叉验证，选择超参数；再用选出的方案预测外层留出数据。外层数据不能参与内层选择。

它计算成本更高，适合需要更严格估计选择流程表现的情况。有独立、充分且代表上线分布的最终测试集时，也可采用开发集调参加最终测试的流程。

## 9. 练习与参考答案

1. 同一用户十条记录，用户级任务用分层随机切分够吗？  
   答：不够。分层不隔离用户，需要分组边界。

2. 五折交叉验证后是否直接上线其中最高分那折的模型？  
   答：通常不这样做。选定配置后在全部开发数据上重训，并独立评估。

3. 为提高平均分删除最差一折合理吗？  
   答：除非有独立、明确的数据错误依据，否则会挑选有利结果。先解释最差折为什么差。

4. 地点数只有四个，能用五折 GroupKFold 吗？  
   答：不能，独立组数不足。增加行数不等于增加组数。
