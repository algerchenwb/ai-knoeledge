# 01｜数据泄漏：为什么离线高分，上线却失效？

> 先修：知道“特征是输入、标签是希望预测的答案”。目标：能检查一张训练表是否偷偷包含答案，并正确组织预处理。

## 1. 用考试理解数据泄漏

模型训练像做练习，评估像参加考试。如果练习时看过考试答案，分数再高也不能证明会做新题。数据泄漏指建模使用了真实预测时无法获得的信息。它不一定表现为直接复制标签，也可能藏在统计均值、特征筛选、时间窗口、重复记录或者反复查看测试分数的操作里。

例如在 9 月 30 日预测某 POI 的 10 月客流，9 月客流是可能使用的输入，10 月完整客流则是未来答案。即使字段不叫“标签”，使用 10 月到访人数构造“活跃度”也可能泄漏。

需要区分两件事：泄漏让评估不公平；过拟合让模型记住训练细节。没有泄漏也会过拟合，有泄漏则会掩盖模型本来的泛化问题。

## 2. 一条样本应记录什么？

先定义预测协议，再查数据：

| 要素 | 虚构示例 | 要核对的问题 |
| --- | --- | --- |
| 样本单位 | POI × 预测月份 | 同一地点是否有重复或近重复记录？ |
| 预测时点 | 9 月 30 日 23:00 | 那时真的可以拿到该特征吗？ |
| 标签窗口 | 10 月 1—31 日客流 | 答案什么时候才能完整产生？ |
| 特征窗口 | 截至 9 月 29 日的过去 90 天 | 是否跨过预测时点？ |
| 可用时间 | 聚合结果 9 月 30 日完成入库 | 事件发生时间和入库时间是否混淆？ |

业务补充：数据可能发生在过去，却在预测后才补录。离线用最终修订表重建历史输入，会得到线上当时没有的信息。应按当时可用的快照或可用时间做关联，这通常称为 point-in-time correct。

## 3. 最常见的五种泄漏

### 3.1 先用全量数据学习预处理，再切分

标准化需要学习均值和标准差。假设训练客流是 10、20，测试客流是 100。训练均值是 15，全量均值约 43.33。用全量均值，训练输入的表示就受测试数据影响。

错误顺序：

```python
X_scaled = scaler.fit_transform(X)
X_train, X_test = train_test_split(X_scaled)
```

正确顺序：先划分，再让 scaler 只在训练集学习参数；测试集沿用这些参数。不仅标准化如此，缺失值填充、PCA、词表学习、特征选择等涉及学习数据统计的步骤也要遵守边界。固定的单位换算等不从数据学习参数的变换，应另作区分。

### 3.2 用标签筛选特征时看过测试集

假设随机生成一万列无意义特征，从全量数据里筛出最关联标签的 25 列。很多偶然相关会被挑中；由于筛选看过测试标签，这些相关也包含了测试集的巧合。再切分和训练，就可能对完全随机的任务得到虚高分。

所以“模型 fit 没有碰测试集”还不够：前面的特征筛选同样属于训练过程。

### 3.3 同一对象出现在两边

同一个 POI 的记录高度相似。若上线任务是预测从没见过的地点，按行随机切分会把同一地点的不同记录分到训练和测试，模型可能记住地点身份。

但如果真实目标是预测已知地点的未来月份，完全隔离地点回答的是另一种问题。这时优先确保时间边界。切分策略必须对应上线任务，不能机械套用。

### 3.4 特征中藏着未来结果

“下月是否营业”“本月最终总量”“预测后处理完成的状态”都值得排查。不能只看字段名，要看计算 SQL、时间窗口、更新机制和入库延迟。

过去 90 天的特征窗口和未来 30 天的标签窗口并非天然泄漏；关键是特征确实只使用当时可得数据。若不同样本的标签窗口重叠，则还需评估训练标签是否在验证预测时点前已成熟。

### 3.5 反复看测试集，再决定改什么

试了很多模型，每次都用同一测试分数决定下一次修改，测试集就参与了选择。它逐渐变成验证集，即使代码没有把测试行传给 fit，也失去了作为独立最终评估的作用。

## 4. Pipeline 如何保护预处理边界？

下面是独立教学示例，使用随机合成数据，适用于近似独立的二分类样本：

```python
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import balanced_accuracy_score

X, y = make_classification(
    n_samples=600, n_features=8, n_informative=4, random_state=42
)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, stratify=y, random_state=42
)
model = make_pipeline(
    SimpleImputer(strategy="median"),
    StandardScaler(),
    LogisticRegression(max_iter=1000)
)
model.fit(X_train, y_train)
pred = model.predict(X_test)
print(balanced_accuracy_score(y_test, pred))
```

Pipeline 的 fit 按顺序学习各步骤。预测时复用已学到的填充值、缩放参数和模型。把整个 Pipeline 交给交叉验证，可以让每折的预处理只学习该折训练数据。

Pipeline 不能识别“这个字段来自未来”，也不会自动按 POI 分组。它解决流程中的一类泄漏，业务时间和对象边界仍需自己定义。

## 5. 上线前后的预处理一致性

另一类问题不是泄漏，而是训练和预测的输入含义变了：

- 训练时标准化，预测时传原始值。
- 训练单位是“人”，线上改成“千人”。
- 同名字段的统计口径从去重人数改成到访次数。
- 训练类别编码与线上编码不同。
- 训练缺失值按中位数填充，线上直接置零。

应一起保存预处理和模型，记录特征名、顺序、单位、版本、缺失规则，并校验线上输入。相同 JSON 字段名不能保证相同语义。

## 6. 练习与参考答案

1. 预测下月客流，使用“下月是否参加活动”是否泄漏？  
   答：如果预测时已有活动排期且确实可得，可能合理；如果使用事后最终执行情况，就泄漏。不能只根据“下月”二字判定。

2. 先对全量表填充缺失中位数，再切分，是否合理？  
   答：不合理。中位数从数据学习，应只从训练部分学习。

3. 已使用 Pipeline，测试分数仍异常高怎么办？  
   答：检查标签代理字段、未来聚合、重复样本、对象跨集合和测试集参与调参，逐项移除可疑信息并重新评估。

4. 把测试集转化为验证集后如何恢复独立评估？  
   答：明确承认它已用于选择，留出未参与选择的新数据；最好使用后续真实时间窗口。不能简单改文件名宣称它再次独立。
