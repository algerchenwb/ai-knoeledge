# 竞品分析：共访人数、方向比例与排行

本篇为独立业务设计，全部输入与ID虚构；没有连接真实业务系统，也不声称开源项目已经实现这些业务功能。

## 业务问题与决策

商户问：“来过我的店的人，还去了哪些竞品？”这可以形成共访排行，用于理解共享客群；它不证明客户从本店流失到了竞品，也不能推断到访先后。

教学窗口中A、B是两家店的去重到访人群。共访人数C=|A∩B|。以本店A为基准的比例是C/|A|，以B为基准是C/|B|；Jaccard为C/|A∪B|。四个指标回答不同问题，产品字段不能统一叫“重叠率”而不解释分母。

## 从自然语言到接口结果

模型解析reference_poi与竞争集合；候选服务按已约定区域和业态返回稳定ID；共访服务以同一窗口计算各候选；确定性排序器按用户指定指标排序。候选规则、距离、业态版本和统计窗口随结果保存。

教学接口建议query_co_visitation，输出每行candidate_id、overlap、reference_share、candidate_share、jaccard及status。分页和截断信息需保留，否则模型可能把第一页说成全部竞品。

## 可复算案例

A={u1,u2,u3,u4}，B={u2,u4}。共访2人，以A为基准50%，以B为基准100%，Jaccard50%。把同一对店交换位置，人数与Jaccard不变，两个方向比例互换。

```json
{
  "overlap": 2,
  "a_to_b": 0.5,
  "b_to_a": 1.0,
  "jaccard": 0.5
}
```

对应co_visit。排序按共访人数会偏向大规模候选；按比例可能让小样本排在前面。排序键、最小可展示样本策略与并列规则必须明确，不能让模型临时选最符合叙述的一项。

## 业务展示与误读

回答“B的2名到访者均出现在A的4名到访者中；A到访者中有一半也到访过B”。不要改写为“B抢走A一半客户”。若要研究迁移，需要另定义首次/后续到访、比较期间和可观察范围。

多个候选的共访人数不能直接相加：同一用户可能同时到访多家竞品。要计算“去过任意竞品”的占比，应先对候选用户集合取并集，再与A求交。

## 验收与失败出口

离线检查验证非对称比例、空集合和交并集；候选解析、分页、排行与展示阈值尚未实现。生产金标准应加入重复事件、同名店、多围栏与跨窗口混用。

验收关注方向字段正确率、候选覆盖、排行稳定性和重复计数错误。运营活动的效果需另做业务实验，不能由共访表自动推断。
