# 选址推荐：硬约束、可解释评分与缺失数据

本篇为独立业务设计，全部输入与ID虚构；没有连接真实业务系统，也不声称开源项目已经实现这些业务功能。

## 业务问题与决策

连锁团队想从候选地点选几个做现场调研。Agent的合理交付是候选清单、证据、评分理由和缺失项，最终经营决策仍需要租约、现场及业务审查。不能把一个分数包装成投资回报预测。

先定义硬约束，例如预算、区域与必需设施。只有通过硬约束的候选才进入评分。再定义软指标与方向：需求、可达性、成本适配均转成0—100且越大越好。成本适配不是租金原值，转换方法需固定。

## 业务编排

对象服务返回候选ID和位置；约束服务检查资格；数据服务提供每项指标及版本；确定性评分器计算贡献；Agent根据贡献组织解释。工具回调与共享上下文的开源机制可以承载这条流程，具体选址规则是本文设计。

保存score_config_version、feature_version、eligibility_reasons与missing_fields。避免模型在看到答案后临时改权重。比较区域不同、密度不同的数据时，归一化参考范围必须一致。

## 手算案例

需求80、可达性60、成本适配40；权重分别0.5、0.3、0.2。贡献为40、18、8，总分66。对应site_score，Decimal确保权重求和与显示稳定。

```json
{
  "status": "ok",
  "score": "66.0",
  "contributions": {"demand": "40.0", "access": "18.0", "cost_fit": "8.0"}
}
```

若硬约束不通过，返回ineligible，不继续给分。若关键指标缺失，返回missing_features与score=null；不默认为0，也不静默把剩余权重重新归一化。后两种处理都会改变评分含义。

## 如何呈现推荐

建议每张卡片包含候选、通过的条件、各指标贡献、证据时间和待核实事项。优先给出“值得进一步调研”的结论，并解释主要优势与不足。总分接近时展示区分证据与不确定性，而不是输出过度精确的唯一排名。

权重敏感性可以作为后续试点：改变合理权重范围，看候选排序是否翻转。本例没有进行敏感性实验，66分也不是预测成功率66%。

## 验收标准

检查硬约束、缺失字段、权重总和、数值范围、单位方向和同名候选；人工复核解释是否忠实于贡献。离线示例验证手算贡献与失败边界，尚未接地点解析、数据归一化和真实排名。

业务收益以调研筛选时间、证据完整度与人工修正率评估；不能用模型自评分替代真实选址结果。
