# AI辅助报价：价目表、阶梯价格、折扣权限与有效期

客户说“我们需要150次区域分析，再加一次初始化，能优惠一点吗？”AI可以整理需求、解释方案和生成报价草稿，最终金额应由价格规则服务计算。销售最需要避免的是错套阶梯、擅自给折扣、使用过期价格或把未含税价格当成最终应付金额。

本篇在[报价文档金额复核](10-quote-document-validation.md)基础上，补齐报价如何产生和再次使用前如何检查。适合SaaS售前、API套餐报价、实施服务组合和内部商务助手。所有SKU、金额、折扣及客户均为虚构教学数据，不代表任何产品实际价格或商业承诺。

## 1. 把客户需求映射为明确销售项

原话“分析150次”可能指API请求次数、区域数量、报告份数，或一个月的分析额度。数量相同但计费单位不同，金额没有可比性。

先核对产品、SKU、计费单位、数量、服务周期和必要的一次性费用。模型可以提出候选，最终SKU由受控产品目录解析。缺少计费单位或客户无法确认时，应保留待确认项，不用最相似的名称直接报价。

示例使用`analysis-unit`和`setup-once`两个SKU，分别假定为一次分析服务和一次初始化。没有自然语言解析、套餐权益或单位换算。生产需要区分“购买额度”和“实际消耗”，不能把消耗统计直接当作报价数量。

## 2. 价目表应有版本、币种和生效区间

| 字段 | 教学值 | 业务用途 |
|---|---|---|
| version | rate-demo-2 | 追溯价格来自哪份表 |
| currency | CNY | 防止人民币和美元混算 |
| start / end | 2026-09-01 / 2026-11-01 | 限定价格生效区间 |
| SKU与阶梯 | 前100单位2.00，之后1.50 | 明确计价方法 |
| policy.version | discount-demo-1 | 绑定折扣与有效期政策 |
| automatic_discount_limit | 0.10 | 自动价格检查允许的最大减免比例 |

价目表通常应由产品或商务团队维护，Agent查询有效版本。客户提交的旧报价、销售聊天记录和上传文档可以成为核查资料，不能直接覆盖当前受控价格。

生效区间采用起始日包含、结束日不包含。生产还要考虑客户合同特价、区域价格、订阅周期和渠道政策。本文只演示一份内部夹具价目表，不处理合同例外。

## 3. 分段计价与整量阶梯计价差别很大

两种规则都可能叫“阶梯价”，必须明确是哪一种。

| 规则 | 150单位的计算 | 原价合计 |
|---|---|---|
| 分段计价（本文实现） | 前100×2.00，余下50×1.50 | 275.00 |
| 整量阶梯计价（未实现） | 达到第二档，全部150×1.50 | 225.00 |

示例`pricing_mode=graduated`，每个阶梯上限表示累计数量，最后一档无上限。程序输出各段数量、单价与段金额，便于客服和客户复核。

在100单位时原价为200.00；101单位时为201.50。它不会把前100单位重新按1.50计价。真实合同如果规定整量阶梯，应实现另外的模式并单独验收，不能改变解释文字却沿用同一计算函数。

## 4. 重复SKU不能随意拆行或合并

客户要150单位，拆成两行75单位可能导致每行都停留在第一档，得到300.00。合成一行150单位则为275.00。因此同SKU的聚合范围属于业务规则，而不是表格排版问题。

本文拒绝重复SKU，要求上游先确认应按哪一份商业需求聚合。也不支持同SKU不同周期、不同地区或不同权益混用。生产可将SKU、合同期、计费单位、适用地区等组成完整销售项键。

行输入仅允许`sku、quantity、discount`，不接受模型随意指定`unit_price`。未知SKU会拒绝，避免AI编造不存在的销售项或用客户要求的低价替代权威价格。

## 5. 用减免比例表示折扣，避免“九折”误读

示例`discount=0.10`表示减免10%，客户通常称“九折”，计算为原价×0.90。它不表示只收原价的10%。

150单位原价275.00，减免10%后为247.50；初始化原价50.00、不打折，两行税前合计297.50。输出保存每行原价、减免比例和净额，使销售能解释数字如何产生。

本文政策允许最高10%的减免比例进入`pricing_checked`状态。20%减免仍可计算草稿，但状态是`needs_discount_approval`，再次核对不能放行。程序没有真实审批接口，也不允许通过传一个`approved=true`字段绕过政策。

“价格检查通过”不等于已获对外报价权限。正式商业方案还可能涉及毛利底线、付款条件、承诺交期和合同条款，应由相应业务流程审核。

## 6. 金额精度与舍入顺序需要写进规则

程序使用Decimal和十进制字符串，避免把二进制浮点数当作价格。数量必须是1到10000的整数，布尔值不能当数量，负数与小数数量也会拒绝。

教学规则先合计每行分段原价，再乘折扣，按`ROUND_HALF_UP`舍入到两位小数，最后加总各行净额。不同舍入顺序可能产生不同总数，因此报价、账单和人工复核应使用同一规则版本。

例如单价0.05、数量1、减免10%，数学值为0.045，逐行舍入后为0.05。小金额时显示的实际减免可能小于名义比例；对客户展示应说明适用的金额精度。本文没有处理多币种不同小数位和优惠券分摊。

## 7. 币种、含税口径与额外费用分开表达

示例只接受与价目表一致的币种，不进行汇率换算。CNY价目表收到USD请求会拒绝，不能简单把币种标记改成USD。

所有金额明确标为税前，税费和其他费用未计算。297.50只是本例销售项净额合计，不是已核定的最终应付金额。模型生成文档时必须保留这项限制。

生产若涉及税费、运输、实施费用或跨币种，应接入对应权威规则并保存适用范围、版本与计算结果。本文不提供真实税率、汇率或发票规则，也不生成账单、发票或付款单。

## 8. 报价有效期不能超出价目表范围

示例最多允许14天报价有效期。2026-10-05生成的14天草稿，到2026-10-19不再有效；结束日不包含。

若2026-10-25生成14天草稿，但价目表2026-11-01结束，有效期被截到11月1日。这样不会用已失效的价格延续报价。真实合同可能允许锁价，但必须是明确的例外政策，本例不实现。

查询日期和再次核对日期应来自可信服务，不能由模型自行填早日期来使用旧价。本文为了测试日期边界允许显式输入日期；不是实际时间认证机制，也不处理小时级生效或跨时区报价。

## 9. 使用报价前重新核对金额与版本

`recheck`先校验稿件摘要，再从行数量与折扣重新计算，对比整个报价正文。修改总价后即使重算SHA-256，也会因与受控价目表不一致而拒绝。

正文同时绑定租户、客户、币种、价目表版本、折扣政策版本和有效期。把同一份报价换成另一客户，也会被重新计算与比对发现。当前价目表或政策版本改变时，旧稿不能继续通过检查。

这依赖服务中的价格与客户上下文可信。摘要不是签名，程序没有真实登录、客户授权、数据库不可变快照或批准来源校验。生产应由身份中间件绑定客户与租户，价目表由受控服务提供。

重新核对只返回`pricing_rechecked`，不表示报价已发送或已成交。发送后的实际回执、客户接受、合同签署和收款应另行记录。

## 10. 开源文档解析如何参与报价流程

[Docling固定提交README](https://github.com/docling-project/docling/blob/58f1f8d907fdc4610cd8dca20da6ef53a4550ee8/README.md)介绍文档解析、表格结构理解、统一文档表示和Markdown/JSON等导出方式。它可以作为处理客户需求书、历史报价PDF或产品资料的文档入口参考。

推荐流程是：解析保留原文位置；提取SKU、数量、单位与金额候选；核对受控产品目录与价目表；确定性计算草稿；人工复核含糊内容；生成带版本与限制的商务文件。解析器读到的数字只是候选字段，不能自动成为当前价格规则。

本文的分段计价、折扣权限和有效期是独立业务设计，上游Docling不自动提供这些政策。没有安装或运行Docling，没有解析真实PDF或调用模型。[来源记录](examples/business-quote-pricing-sources.json)保留固定SHA与学习范围；已有[MIT许可副本](../agent-case-studies/licenses/docling.txt)。模型资产许可证应按其各自来源核对。

## 11. 运行与已验证内容

```bash
python knowledge/business-ai-cases/examples/business_quote_pricing.py
python knowledge/business-ai-cases/examples/test_business_quote_pricing.py
```

[源码](examples/business_quote_pricing.py)只依赖Python标准库。`build`返回明细草稿、价格状态和摘要，`recheck`重新计算并检查版本与日期。行顺序按SKU固定；程序没有数据库写入或对外发送。

2026-10-05在Python3.12.14运行[20项检查](examples/test_business_quote_pricing.py)，全部通过：分段金额与边界、多行合计、舍入、折扣阈值、重复/未知SKU、数量与金额类型、币种、价目表生效、有效期截断与过期、版本变化、篡改金额、客户绑定、阶梯结构和输入白名单。[运行记录](examples/business-quote-pricing-results.json)包含297.50正常草稿与需审批的优惠草稿。

这些检查限于虚构税前规则与可信上下文，不覆盖自然语言需求理解、文档抽取准确率、真实折扣审批、合同特价、税费、汇率、账单、发票或支付系统。

## 12. 业务试点与练习

先整理已授权的历史需求和人工报价，逐题记录计费单位、计价模式、适用版本、折扣权限和金额。分别统计SKU错配、数量遗漏、价格错用、超权限优惠、过期稿使用和金额差异，不只看是否生成了一份文档。

作为内部草稿试点，比较人工核价时间、返工次数与审批退回原因。正式收益应来自真实流程记录；本文不虚构节省成本或成交提升。

练习：把151单位的原价手算为276.50，再检查减免10%的净额248.85；增加一个按年售卖的SKU，先确认单位与合同期，再设计重复行聚合规则。进一步接入真实折扣审批时，应绑定客户、报价摘要、批准上限与有效期，并在对外发送前重新核验。
