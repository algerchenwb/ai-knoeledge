# Agent 路由与协作

依据handoff、任务依赖和消息运行时。角色个数不是质量指标；分工应该对应能力、证据或权限边界。

## 021. 规则路由与模型路由

**应用场景：**精确指令和模糊问题混在一起。

**实现步骤：**明显协议或业务码用规则，语义歧义交给模型；记录route_reason与候选。

**验收方法：**固定输入不会被随机转到不同处理域。

**常见误区：**让模型替代所有确定性判断。

## 022. Handoff控制权

**应用场景：**客服转到专业处理域。

**实现步骤：**保存current_agent及共享上下文，明确回退路径与转接原因。

**验收方法：**下一轮仍到当前专员，任务结束才回到分诊。

**常见误区：**把专家咨询返回结果误当会话控制权转移。

## 023. 专家作为工具

**应用场景：**主Agent只需要一段专项分析。

**实现步骤：**专家限定输入输出，主Agent拿结果后继续组织回复；给子任务单独预算。

**验收方法：**专家失败能被主流程识别并降级。

**常见误区：**专家输出无限扩写，占满主任务上下文。

## 024. 顺序任务依赖

**应用场景：**先研究再写报告。

**实现步骤：**建立依赖图，传递产物ID与版本；上游改变时使下游旧结果失效。

**验收方法：**未完成研究不能进入正式发布。

**常见误区：**仅靠角色提示隐式继承资料。

## 025. 并行独立任务

**应用场景：**查两个互不依赖的数据源。

**实现步骤：**并行调用后按键汇合，各分支保存状态与错误，限制并发数。

**验收方法：**一支失败时另一支结果仍可保留。

**常见误区：**共享可变状态导致覆盖或重复写。

## 026. 协调者与最终责任

**应用场景：**多个Agent都给出部分回答。

**实现步骤：**协调者按覆盖表汇总，明示冲突并指定最终结果责任者。

**验收方法：**同一指标冲突不会被悄悄平均。

**常见误区：**让最后发言的Agent天然代表正确结论。

## 027. 有界反思

**应用场景：**生成失败后不断自我检查。

**实现步骤：**规定最多N次修正，每次必须有新观测或明确修改；无进展则退出。

**验收方法：**同一错误重复时停止并报告原因。

**常见误区：**把反思次数增加当作质量保证。

## 028. 工具反馈优先

**应用场景：**模型认为任务已成功。

**实现步骤：**使用真实退出码、返回对象与产物校验更新状态；文字自评只作辅助。

**验收方法：**没有真实结果就不会标记done。

**常见误区：**模型说已写入即当数据库提交成功。

## 029. 终止条件分层

**应用场景：**消息系统空闲但任务没完成。

**实现步骤：**分别检查运行结束、产物完成、业务目标达成；状态机包含失败和取消。

**验收方法：**空闲却缺产物的任务记录为未完成。

**常见误区：**没有更多消息就等于成功。

## 030. 协作成本基线

**应用场景：**考虑从单Agent改多Agent。

**实现步骤：**先固定题集测单Agent，新增分工后比较正确率、费用、延迟和交接错误。

**验收方法：**有量化增益再保留新增节点。

**常见误区：**只展示一次漂亮演示，没有对照。
