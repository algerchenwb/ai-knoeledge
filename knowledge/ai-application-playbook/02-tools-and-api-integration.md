# 工具调用与 API 接入

依据类型化API、客服工具与网关MCP桥接机制。鉴权、幂等与预算配置均需在实际服务端实现，不能从工具描述推断已具备。

## 011. 工具语义分组

**应用场景：**几十个接口让模型容易选错。

**实现步骤：**按业务能力提供少量入口，内部映射底层API；描述注明适用与不适用条件。

**验收方法：**相似问题选择正确能力，错误选择可追溯。

**常见误区：**给每个HTTP路径都创建一个Agent。

## 012. 参数白名单

**应用场景：**模型生成未知字段。

**实现步骤：**工具schema约束字段、枚举、长度与批量数量，服务端重复校验。

**验收方法：**非法字段拒绝或明确忽略，不透传后端。

**常见误区：**认为模型端schema已等于服务器安全校验。

## 013. 鉴权上下文注入

**应用场景：**用户让Agent查询另一租户。

**实现步骤：**身份和tenant_id来自已验证会话，由服务端注入工具；不接受模型选择身份。

**验收方法：**越权ID即使格式合法也被拒绝。

**常见误区：**把用户文字中的租户名当授权。

## 014. 分页与截断标记

**应用场景：**接口只返回前100条。

**实现步骤：**工具返回has_more、next_cursor与total口径；Agent按预算继续或声明覆盖范围。

**验收方法：**摘要不会把第一页当全量。

**常见误区：**只传列表，不告诉模型被截断。

## 015. 批量查询映射

**应用场景：**一次查询多个区域对象。

**实现步骤：**每项结果保留输入ID与status；部分失败独立记录，不按数组位置盲配。

**验收方法：**顺序打乱、缺失一项仍能正确对应。

**常见误区：**一个失败导致全部有效数据丢弃。

## 016. 错误分类

**应用场景：**HTTP200里业务码表示失败。

**实现步骤：**分别解析传输、鉴权、业务与数据错误，映射统一error_type和retryable。

**验收方法：**200失败不会记为成功，401不会当空数据。

**常见误区：**只凭HTTP状态做最终判断。

## 017. 只读与写工具分离

**应用场景：**同一助手能查询与创建任务。

**实现步骤：**工具元数据标记副作用；写操作绑定授权、幂等键与结果查询接口。

**验收方法：**重复调用不会重复创建同一业务对象。

**常见误区：**所有错误都自动重试写请求。

## 018. 超时与截止时间

**应用场景：**串联三个慢接口。

**实现步骤：**请求携带整体deadline，各步骤只使用剩余预算，取消传播到下游。

**验收方法：**总耗时有上界，不能每一步都重新获得完整超时。

**常见误区：**给三个接口各60秒却宣传任务60秒内完成。

## 019. MCP工具适配层

**应用场景：**已有HTTPAPI需要供多客户端使用。

**实现步骤：**将输入schema、工具描述、错误与真实调用分层；记录工具版本和后端响应摘要。

**验收方法：**客户端看到一致协议，旧版本有兼容测试。

**常见误区：**支持MCP就认为自动支持所有OAuth流程。

## 020. 工具结果压缩

**应用场景：**后端响应包含巨大JSON。

**实现步骤：**提取完成任务必需字段，附source_id和截断信息；大结果保存为可寻址产物。

**验收方法：**压缩后仍能核对对象、时间、单位和错误。

**常见误区：**删掉状态与来源，只留下数值。
