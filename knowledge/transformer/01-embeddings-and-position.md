# Embedding 与位置：模型怎样把文字变成数字

## 先建立直觉

模型不能直接对汉字做矩阵乘法。Tokenizer 先把文本切成 token，再把每个 token 映射成整数 ID；Embedding 层用 ID 查表，得到一串浮点数。这串数是后续网络计算的起点，不是人类提前写好的词义字典。

可以把 ID 理解成图书编号，把 embedding 理解成模型学习的特征卡。编号 100 与 101 相邻，不表示两本书内容相似；特征卡的距离才可能反映训练任务需要的关系。向量某一维通常没有稳定的“收入”“年龄”之类人工含义。

## 从形状读懂计算

假设词表大小 V=10000，表示维度 D=128，输入批次 B=2，每条序列 T=6。

| 对象 | 形状 | 含义 |
| --- | --- | --- |
| token IDs | [2,6] | 两条序列的编号 |
| embedding 参数表 E | [10000,128] | 每个编号对应128个数 |
| 查表输出 X | [2,6,128] | 每个位置的初始表示 |
| 最终 logits | [2,6,10000] | 各位置对下个token的候选分数 |

查表不是把 ID 数值乘以权重。它选出 E 对应的行。训练通过梯度更新被使用的表示及其他参数；具体优化器、权重衰减和参数共享会影响实际更新。

这里 embedding 表有 128万参数；若每个参数使用2字节，纯参数占用约256万字节。训练还有梯度、优化器状态、激活等开销，不能拿这个数字当训练显存。

## 为什么还需要位置

“甲收购乙”与“乙收购甲”包含相同词，却表达不同关系。基本注意力打分机制本身没有直接提供完整序列顺序信息，因此模型需要位置机制。因果掩码也提供方向限制，但不能替代所有位置表达。

nanoGPT 的 GPT-2 风格实现使用可学习绝对位置表：X=token_embedding+position_embedding。第0个位置和第1个位置查不同的参数行。它的 block_size 限制位置表支持的长度；把长输入截断能运行，却会丢失早期信息。

另一类常见机制是 RoPE：在注意力中按位置旋转 Q/K，使打分能表达相对位置关系。本文用它作概念对照，没有声称 nanoGPT 的这份代码使用 RoPE。绝对位置、RoPE 和其他方案的长文本行为需要分别验证，不能只修改配置数字就保证有效外推。

## 同一个词为什么有不同解释

查表初始向量主要由 token ID 决定，但经过注意力和多层网络后，表示结合上下文。“苹果发布新品”与“苹果成熟了”中的相关 token 可以得到不同的上下文表示。初始 embedding 与上下文 hidden state 要分开理解。

语义搜索的句向量又是另一层：它通常把整段文本压缩成固定维度表示，并针对检索或相似度任务训练。语言模型内部任意一层的平均值不自动成为优质搜索向量。维度相同也不意味着两个模型的向量能混用。

## 权重共享是什么

nanoGPT 将 token embedding 与输出 lm_head 的权重共享。输入时查表，输出时用对应矩阵把隐藏表示转换成词表分数。共享减少独立参数，也建立输入与输出词表表示的联系。统计参数时不能把同一份共享存储算两遍；并非所有模型都采用该设置。

## 后端工程例子

你的 API 文档索引升级 embedding 模型后，原向量库不会自动兼容。正确迁移是记录模型版本、维度、归一化、分块和输入模板；重建新索引；用同一组查询比较召回；再切换读流量。仅检查“都是1024维”不足以证明兼容。

## 常见误区

- token 数不等于字数，必须使用对应 tokenizer 计算。
- embedding 大小不是整个模型大小。
- 向量近不保证逻辑等价，“允许退款”和“不允许退款”可能共享很多语义。
- 位置上限与长文本任务正确率是不同指标。

## 练习与答案方向

词表变成20000，D不变，embedding 参数是多少？答案256万。B或T增大是否增加模型参数？不会，只改变当前计算和激活规模。搜索模型改变、维度不变能否直接复用旧向量？通常不能。
