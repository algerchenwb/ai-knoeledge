# 排序指标深入：NDCG的增益、并列与候选集

## 先固定“评估谁”

已有[检索评估](../retrieval/01-similarity-and-embedding-evaluation.md)介绍Recall、MRR与NDCG的用途。本篇深入计算约定。排序指标把候选分数降序排好后，查看相关文档是否靠前；它不检验相似度分数有没有概率含义。同一模型在“全库候选”和“1个正例加99个随机负例”上，分数可能完全不同，不能直接横比。

$$\mathrm{DCG}@k=\sum_{j=1}^{k}\frac{g(r_j)}{\log_2(j+1)},\qquad \mathrm{NDCG}@k=\frac{\mathrm{DCG}@k}{\mathrm{IDCG}@k}.$$

`r_j`是第j位的相关等级，IDCG是把同一组候选按真实等级理想排序后的DCG。非负增益下范围通常是0到1。常见增益有`g(r)=r`和`g(r)=2^r-1`；后者更强调最高等级。scikit-learn的`ndcg_score`使用**输入的真实分值直接作为增益**。若需要指数增益，应先转换标签，再调用；不能只把函数名相同当成定义相同。

## 手算一个列表

预测顺序对应等级`[2,3,0]`，使用线性增益，DCG@3=`2+3/log₂3`约3.8928；理想顺序`[3,2,0]`的IDCG约4.2619，因此NDCG约0.9134。若采用指数增益则把等级改为`[3,7,0]`，得到不同答案。这不是某个库算错，而是增益定义不同。

MRR只关心第一个相关项：先定义相关阈值，如果首个相关项位于第j名，RR=1/j；没有相关项则为0。多个查询求平均得到MRR。它对后面的相关文档不敏感，所以多篇证据任务应结合Recall或分级指标。

## 边界决定可比性

| 情况 | 应记录的约定 |
| --- | --- |
| 所有候选相关度为0 | IDCG=0时的返回值；sklearn返回0 |
| 预测分数并列 | 平均可能排序或稳定打破并列；sklearn默认平均并列贡献 |
| 只有部分文档标注 | 未标注不能轻率当已确认不相关；说明标注池 |
| 多个查询 | 逐查询平均还是按权重平均；是否排除无正例查询 |
| top-k截断 | k、候选集合和缺失正例是否一致 |

仅在确认没有分数并列时才使用`ignore_ties=True`。将相同分数随意加一个很小的扰动会改变排序政策；不能靠这种做法掩盖并列。评估集还应固定去重方式：同一文档的多个chunk不应无意重复贡献“命中”。

## 实验与思考

[脚本](examples/06_ranking.py)把独立手算DCG与sklearn比较，检查完美排序、无相关项、线性与指数增益差异以及一个完全并列的案例。运行：`python knowledge/applied-algorithms/examples/06_ranking.py`。

练习：系统A在完整库测得0.7，系统B在随机负采样集合测得0.9，能否认为B更好？不能；先固定候选、标注、增益、并列与k，再比较。离线相关度排序也不保证在线收入或证据准确性。
